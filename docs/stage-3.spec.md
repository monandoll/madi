# Stage 3 — 파이프라인 연결

`AGENTS.md §12-3`. 2단계 통과(`stage-2`, 2026-09-27) 뒤에 시작한다.

```
PhotoKit 가져오기 → 다이제스트 → 큐 → 렌더 → 갤러리.  AI 없이 수동 Composition 으로.
통과: 아이폰으로 찍은 영상이 앱에 저절로 뜨고, 3분 안에 완성 영상이 나온다 (Apple Silicon 기준)
Intel 폴백(WhisperCppProvider)도 붙이고 동작만 확인한다. 시간은 재지 않는다
```

**닿는 단위에서 하나씩** 안과 권장을 가져간다 — 3번(다이제스트)에서 모델 받기 · 저장 위치,
6번에서 Universal · Intel.

## 정해 둔 것

- **전사 모델 — 받아서 쓴다 (2026-09-27 결정 A).** 앱에 넣지 않는다 (넣으면 업데이트마다 484MB).
  **첫 실행이 끝나자마자 백그라운드로 받기 시작한다** — 크리에이터의 첫 영상이 다운로드를 기다리지 않게.
  받은 뒤 바로 한 번 데운다(CoreML 컴파일 ~50초). 공식 배포처(WhisperKit HuggingFace 모델 저장소) ·
  버전 고정 · 해시 확인 — 글꼴 목록(`findings/2026-09-27-font-catalog.md`)과 같은 방식으로 같이 만든다.
  모델은 `small` 유지. 준비 상태 문구 키는 `docs/design/copy-keys.md` 에 넘겼다.
  `§2` "첫 실행 준비 화면도 필요 없다" · `§3` 네트워크 문장은 이걸 만들 때 한 번에 고친다

- **"수동 Composition"** — 3단계에는 AI 가 없다. 편집안은 사람이 쓴 JSON 을 영상에 붙인다.
  `§10` 대로 **AI 없는 편집 경로를 제품에 만들지 않는다** — 수동 편집안은 3단계 판정용 입력이다
- **렌더 결과물은 항상 편집안에서 재현 가능** (`§1-8`) — `outputs` 는 `compositionID` 를 가리키고,
  편집안은 `style {id, version}` 을 가진다
- **UI(`Madi/UI/**`)는 디자인 쪽 소유** — 갤러리 화면은 개발이 만들지 않는다.
  개발은 갤러리가 읽을 **관측 가능한 데이터**(GRDB `ValueObservation`)와 문구 키를 넘긴다.
  3분 판정에 필요한 "저절로 뜬다" 는 DB 에 들어온 시각으로 잰다 (화면 없이도 잴 수 있다)
- 저장 위치 — `~/Library/Application Support/madi/` (DB · 원본 사본 · 결과물),
  중간 산출물은 `~/Library/Caches/madi/<compositionID>/` (`§7`)

## 성능은 Release 빌드로만 잰다

Debug 빌드는 Swift 루프 최적화가 꺼져 있어 **착시가 크다.** 사람 추적(분할 마스크를 묶는 루프)이
17.5초 영상에서 Debug 46.8초 → Release 8.9초였다. Vision 호출 자체는 35프레임에 2.0초뿐이었다.
3분 판정 · `events` 성능 기록은 Release 빌드 기준이다.

다이제스트 한 편 (`8DF9jrxQM4U`, 17.5초, Release, 모델 데운 뒤): 전사 3.4 · 사람 9.0 · 컷 4.5 · 시트 1.3 · 소리 0.1 = **18.3초**.
모델이 차가울 때(이 바이너리로 처음) 전사가 **약 50초** 더 든다 — CoreML 컴파일. 새 빌드마다 한 번.

## 3분 판정 (5번)

```
t0 아이폰 촬영 종료 → t1 DB 에 영상 행이 생김(가져오기) → t2 다이제스트 완료 → t3 렌더 완료
통과: t3 − t1 ≤ 180초 (Apple Silicon). t1 − t0 은 iCloud 동기화라 따로 적는다 (우리가 줄일 수 없다)
```

- `events` 에 단계별 시각과 아키텍처를 남긴다 (`§14`)
- 촬영본은 1분 안팎, 촬영 규칙(`§11`)을 지킨 것으로 잰다
