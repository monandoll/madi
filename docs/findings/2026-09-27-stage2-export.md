# 2단계 판정 — 내보낸 영상에서 G4 · G5 · G6 · G7 (2026-09-27)

`AGENTS.md §12-2` 통과 조건은 G4 · G5 · G6 · G7 이다. 지금까지는 따로따로 확인했다 —
G4 는 스타일 값으로 계산, G5 · G6 은 분절 결과로. **내보낸 영상 위에서 잰 적이 없었다.**
재 보니 **내보낸 영상에 우리 자막이 없었다.** 전작 실패 원인 `§0-6`("렌더 결과를 아무도 다시 안 봄")이 그대로 있었다.

도구: `madi-spike stage2 <영상> --slot <슬롯>`
```
전사(WhisperKit small) → CaptionSplitter → 편집안(style = 최신 버전) → 렌더(내보내기)
                                                       └→ 같은 편집안을 자막 없이 한 번 더 렌더
자막마다 한가운데 시각에서 두 파일의 프레임을 뽑아 차이를 본다 — 차이 = 우리가 그린 자막
```
공개본에는 크리에이터 자막이 이미 박혀 있어서 차이로만 우리 자막을 가려낼 수 있다.
프레임은 **내보낸 mp4** 에서 뽑는다 (§7 — `animationTool` 은 내보내기에서만 적용된다).
편집안은 `out/stage2/<id>/composition.json` 으로 남긴다 (§1-8).

## 1. 버그 두 개

### (1) 내보낸 영상에 자막이 아예 없었다

`CaptionLayer` 는 `setNeedsDisplay()` 만 부르고 `draw(in:)` 에서 CoreText 로 그린다.
그런데 `AVVideoCompositionCoreAnimationTool` 의 오프라인 내보내기에서는 **표시 주기가 돌지 않아
`draw(in:)` 이 한 번도 불리지 않았다.** 레이어는 비어 있었다.

→ 레이어를 만들 때 `displayIfNeeded()` 로 바로 그린다. 렌더할 때마다 레이어를 새로 만들고
  CoreText 로 다시 그리므로 "자막을 미리 굽지 않는다"(§14)와 어긋나지 않는다.

세션 시작 커밋(`675ef39`)을 따로 빌드해 같은 편집안을 그려도 자막이 없었다 — 오늘 생긴 문제가 아니다.

### (2) 고치자마자 — 모든 자막이 0초부터 겹쳐 떠 있었다

사라지기 애니메이션(opacity 1→0)을 `fillMode = .both` 로 두어서, **시작 전 구간에 fromValue(1)가 채워졌다.**
같은 opacity 를 잡은 나타나기(시작 전 0)를 덮어서, 모든 자막이 0초부터 자기 끝 시각까지 보였다.
(1)번 때문에 아무것도 안 그려져서 드러나지 않았던 버그다.

→ 사라지기는 `.forwards`, 나타나기 · 튀어나오기는 `.both`.

### 회귀 테스트

`ExportCaptionTests` — 자막 없는 단색 원본에 자막을 그려 내보내고, **내보낸 파일에서**
시작 전 · 도중 · 끝난 뒤의 흰 글자 픽셀을 센다. 고치기 전: 도중 **0개**, 다음엔 시작 전 **509개**. 고친 뒤 통과.

## 2. 0단계 B 판정은 가짜 통과였다

`2026-09-25-coretext-caption-measurement.md §8` 은 "우리 렌더" 가 원본과 **자릿수까지 같다**
(3.54% · 0.2354 · 0.2026)고 적었다. 우리 자막이 없었으니 그건 **원본에 박힌 크리에이터 자막을 다시 잰 값**이다.
자막이 이미 박힌 영상을 비교 원본으로 쓰면 "우리 것이 안 그려졌다" 와 "완벽히 포개졌다" 가 구별되지 않는다.
그 문서에 정정 표시를 달았다. 스틸 렌더로 잰 통과 조건 A 는 영향이 없다.

**교훈**: 번인 자막이 있는 원본과 비교할 때는 **차이로 우리 것만 떼어 내서** 잰다. 같은 자리에 같은 값이 나오면 의심한다.
