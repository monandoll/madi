# 오버레이 payload — 공개본 10편 · 오버레이 55개 (2026-09-27)

`Spec.json` 의 오버레이 payload 가 "2단계에서 확정" 으로 비어 있었다.
정하기 전에 공개본 10편을 **0.5초 간격**으로 전부 훑어 오버레이를 하나씩 셌다
(`layout-survey-10` 은 편당 10장이라 1초 안팎으로 뜨는 원 · 화살표를 놓쳤다).

- 도구: `madi-spike sheet` · `frames`, 색은 프레임 픽셀을 직접 읽었다(*표시*). 나머지 색은 눈 추정
- 크기는 프레임 폭(w) 대비, 위치는 가운데 (x, y) 0..1, 시각 ±0.5초
- 번인 자막(흰 본문 · 노란 보조)은 세지 않았다

## 2. 색은 뜻을 따른다 — 그래서 AI 는 색이 아니라 뜻을 고른다

| 색 | 쓰인 곳 |
|---|---|
| **빨강** | 틀린 쪽 ✗ (3편) · 문제 동작 화살표 — 무릎이 안으로 말림 · 무릎 과신전 · 위팔뼈가 앞으로 밀림 · 뭉친 종아리 · 어깨의 깜빡이는 점 |
| **초록 / 노랑** | 맞는 쪽 ○ (`EDpB` 초록 `#66D55A`*, `Uzem` 노랑 `#FDE781`*) — 빨강인 적이 없다 |
| **흰색** | 어떻게 움직일지(곡선 점선 화살표 · 미는 방향 화살표) · 어디를 볼지(퍼지는 점 · 테두리 원) |

예외: `8DF9` 의 흰 ✗, `RnP7` 의 흰 원(실패 조건을 가리킴), `lzDW` 의 빨간 원(누를 곳 — 문제가 아님, *불확실*).
규칙이 엄격하진 않지만 방향은 분명하다. **빨강 = 문제 · 틀림, 초록/노랑 = 맞음, 흰색 = 나머지.**

→ payload 는 `tone`: `problem` · `neutral`. 색은 스타일이 이 이름에 붙인다.
  "맞음" 은 ○ 로만 나왔다 — ○/✗ 는 모양이 곧 뜻이라 tone 을 따로 받지 않는다.

## 3. 종류별 변형

### 화살표 (4편 · 13개)
| 변형 | 편 | 뜻 |
|---|---|---|
| **흰 곡선 점선**, 열린 꺾쇠 머리, **그려지며 나타남** (~0.5초) | `L469` ×3 · `RnP7` ×1 | 이렇게 움직여라 — 가장 흔하다 |
| **실선 + 꼬리 번짐**, 삼각 머리 | `Uzem` (빨강 · 흰) · `L469` (빨강) | 빨강 = 문제 동작, 흰 = 미는 방향 |
| 빨강 실선 곡선 한 쌍 (마주 봄) | `RnP7` | 다리가 안으로 말림 |
| 주황 직선 점선 (그림 카드 위) | `nCsh` | 고관절→무릎←발목 |

양쪽 머리 화살표는 없었다. "양쪽" 은 화살표 두 개로 그렸다.
→ `tone` (problem · neutral) + `path` (straight · curved) + `bend` (곡선이 휘는 쪽).
  점선이냐 실선이냐 · 그려지며 나오느냐는 **tone 과 path 로 스타일이 정한다**
  (neutral 곡선 = 흰 점선 · 그려짐, problem 직선 = 빨강 실선 · 꼬리 번짐).
  끝점은 payload 가 아니라 `Overlay.to` — 좌표 키는 payload 에서 금지 키라서다.

### 원 · 점 (5편 · 12개)
| 변형 | 편 | 크기 |
|---|---|---|
| 흰 테두리 원 | `RnP7` ×2 · `nCsh` ×1 | 0.25w · 0.45w (아주 가는 선) |
| 빨강 테두리 원 | `lzDW` | 0.32w |
| 노랑 가는 테두리 원 (그림 카드 위 관절) | `nCsh` ×2 | 0.16w |
| **빨강 반투명 점, 깜빡이며 퍼짐** | `RnP7` 종아리 · `L469` 어깨 | 0.17~0.18w — 뭉친 근육 |
| **흰 점이 한 번 퍼지고 사라짐** (~0.7초) | `Uzem` · `L469` ×2 | 0.15~0.30w — 여기를 봐라 |

점선 원은 없었다. 테두리 원은 전부 실선.
→ `form` (ring · pulse · tap). ring 만 `tone` 과 `covers` (joint 0.16w · part 0.25~0.32w · area 0.45w).
  pulse(빨강) · tap(흰색)은 모양이 뜻을 정한다.
  ⚠ 노랑 테두리 원(관절 강조)은 1편뿐이라 tone 에 넣지 않았다.

### 그림 · 사진 카드 (4편 · 11개)
- **공통 (4/4)**: 불투명, 각진 모서리, **테두리 · 그림자 · 투명도 없음**, 뚝 나타나고 뚝 사라짐, 카드 바깥으로 영상이 보인다
- 놓는 자리는 편마다 다르다 — `Wp7d` 자막 바로 아래 0.40w 정사각(×4, 차례로 교체) ·
  `nCsh` 0.90w × 0.55H 큰 카드 · `L469` 가로로 꽉 찬 띠 · `Uzem` 왼쪽 아래 세로 카드와 **겹친 4장이 하나씩 들어오는** 콜라주
- `nCsh` 는 큰 카드를 띄우면서 **본문 자막을 위로 올렸다**(y≈0.2)
→ `assetId` + `placement` (under · large · band · side). 여러 장은 오버레이 여러 개 + start 를 늦춘다.
  ⚠ placement 네 개는 **각각 1편 근거**다. 카드가 있다는 것(4편)만 확실하다.
  ⚠ `large` 에서 자막을 옮기는 규칙은 아직 없다 — 그릴 때 정한다.

### ○ / ✗ (4편 · 6개)
- `EDpB` · `Uzem` 은 거의 같은 배치 — **상하 2분할 화면 각 칸의 왼쪽 위**에 ○(위) · ✗(아래), 0.15~0.23w
- 분할 없이 ✗ 만: `8DF9` 흰색 · 둥근 끝 · 0.27w 화면 가운데 / `RnP7` 작은 빨강 ✗ 가 자막 옆에
→ `symbol` (o · x). 새 kind `.mark`.

## 4. 넣지 않은 것

- **상하 2분할 (3편)** — 오버레이가 아니라 장면 레이아웃이다. 칸이 따로 나타나기도 한다(`RnP7`).
  `Scene.layout` + `sources[]` 로 코어 스키마를 건드려야 해서 따로 한다
- 1편에만 나온 것 — Before/After 글자(`Caption.slot == .top` 으로 이미 표현 가능), 장식 손글씨, 3D 뼈 모델, 세로 기준선
- `titleCard` · `counter` · `progress` — 0편. enum 에서도 지웠다

## 6. 측정의 한계

- 0.5초 간격이라 0.5초보다 짧게 스친 것은 놓쳤을 수 있다
- 색은 유튜브 재인코딩본의 픽셀이다. `*` 없는 색은 눈 추정
- 화살표가 몸을 **따라 움직이는지**(`Uzem` 11.75초)와 카드가 **밀려 들어오는지**(`L469` 3.75초)는 불확실하다
- 한 채널 10편이다. 오버레이가 두 편에 몰려 있어서, 이 두 편의 편집 습관이 결과에 크게 들어가 있다
