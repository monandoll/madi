# 실무에 쓸 수 있나 — 남은 문제 (2026-10-01)

사용자: "버그는 다 수정된거야? 실무에서 쓸 수 있을 정도로?????" → **아직 아니다.**
2026-09-30 버그 잡기 세션(PR #43, 29커밋)에서 실제 앱을 두 번 훑어 찾은 것은 다 고쳤다. 이 문서는 **고치지 못한 것 · 확인하지 못한 것 ·
사용자가 정해야 할 것**만 적는다. 고친 것의 목록은 PR #43 본문과 `docs/design/viewdata-map.md` ⑰~㉖.

표기: **눌러 봄**(실제 앱) · **테스트**(단위) · **캡처**(창 캡처를 눈으로) · **안 함**(아무도 안 눌러 봄).

## 1. 정해야 할 것 (사용자 결정)

### 1-1. "앞으로도 이렇게 할까요?" 가 한 번도 안 나온다

- 증거: 앱 DB 채팅 수정 턴 중 새 편집안을 만든 5번, AI 가 일반 규칙(`rule`)을 낸 것 **0번** (`event` 에 `agent.rule.proposed` 0줄).
  요청 — "말이 잘리는 부분이 있어 해당 부분 수정해줘" · "앞에 훅 넣어줘" ×2 · "마지막 장면은 빼줘" · "영상은 20초 안팎으로 줄여줘"
- 마지막 것은 지침에 적힌 **예시 그대로**("영상은 15초 안팎으로")인데도 Codex 가 "이 영상만의 요청" 으로 보고 비웠다 (2026-09-30 23:25, 눌러 봄)
- 원인: 6단계 결정 ③ — 묻는 문장은 AI 가 다듬은 일반 규칙이고, AI 가 비우면 묻지 않는다 (`Chat.swift`, `MadiTools` `rule`).
  AGENTS §10 은 "수정 요청이 오면 고친 뒤 한 번 묻는다" 인데, 지금은 AI 판단에 달려 사실상 꺼져 있다
- 고르는 것:
  - (가) 지침을 바꿔 AI 가 더 잘 내게 — 길이 · 훅 · 자막 · 쉬는 구간처럼 **만드는 방식**에 관한 요청이면 적고, 특정 장면 · 특정 말만 비우게.
    확인에 AI 턴이 여러 번 든다
  - (나) 앱이 늘 묻는다 — AI 가 비우면 크리에이터 말을 그대로 규칙 후보로. 규칙이 지저분해질 수 있다
  - (다) 지금대로 둔다

### 1-2. "너무 자세가 다 안 나와" — 화면을 넓게 담을 방법이 없다

- 사용자가 직접 앱을 쓰다 남긴 말이다 (2026-09-30 23:15, 플랭크 편집안). AI 답: "세로 화면에 맞추면서 몸 양끝이 잘리는 것으로 보여요.
  … 지금은 그 범위를 조절할 수 없어 수정하지 못했어요."
- 원인: 16:9 원본에서 **누운 자세**(플랭크 · 무릎 당기기)는 몸이 가로로 길어 9:16 으로 자르면 머리나 발이 빠진다.
  화면 잡기는 사람 높이(G1)를 키우는 쪽이고, 좌우 잘림은 G2 가 보지 않는다(§8 — 세로 숏폼 기준). AI 는 `reframe` 을 쓸 수 없다
- 대용 원본(남의 16:9 영상)이라 생긴 면이 크다 — 쌤은 세로로 찍는다. 다만 쌤이 가로로 찍은 촬영본이 오면 똑같이 생긴다
- 고르는 것:
  - (가) "넓게 보기" — 원본 전체를 세로 칸에 넣고 위아래를 흐린 원본으로 채운다 (숏폼에서 흔한 꼴). 새 화면 잡기 방식 · AI 가 고를 수 있는 값이 필요 (새 기능)
  - (나) 쌤 세로 촬영본이 올 때까지 미룬다 — 촬영 규칙(`§11` "세로로")으로 막는다

### 1-3. 장면 늘리기 · 빼기를 누를 때마다 편집안이 하나씩 생긴다

- 증거: 2026-09-30 23:09:43 ~ 23:09:52, **9초 사이 편집안 7개** (사용자가 "+ 늘리기" 를 연달아 누름). 버전 목록이 편집안 1~12 가 됐다
- 지금 규칙: 손으로 고치면 항상 새 판 (`AppController.edit`). 바뀌는 게 없는 편집만 막았다 (09-30 `44f2ffe`)
- AGENTS §5 는 "결과물이 있는 컴포지션은 제자리 수정 금지" — **결과물이 없는 판은 제자리에서 고칠 수 있다** (viewdata-map 1절 `canUndo`)
- 고르는 것: (가) 결과물이 나오기 전까지 손으로 고친 것은 한 판으로 묶는다 · (나) 지금대로

## 3. 쌤 영상과 아직 다른 것 (결과 품질)

`docs/findings/2026-09-30-editing-style-30.md` · 나란히 비교 이미지(세션 기록) 기준.
- 화살표 · 원 · ○✗ 표시를 못 그린다 (`OverlayLayer` 미구현, §5 미결)
- 배경음악 · 효과음 없음
- 편 안에서 자막 위치가 움직이는 편 3/10 (`RnP7` · `Uzem` · `nCsh`) — 슬롯 하나 규칙으로 못 맞춘다 (§12 2단계 남긴 것)
- 틀 B(따라하기) 동작 한 장면이 길다 — 쌤 3.6초, 우리 플랭크 초안 4.9초
- 개발 맥의 자막 모양 설정이 **Nanum Pen Script(손글씨, 크림색)** 라 쌤 결과물(굵은 흰 글씨)과 다르게 보인다 — 설정 값이지 버그는 아니다.
  쌤 맥에서는 기본값(Pretendard)으로 시작한다
- 전사 오타가 자막에 그대로 ("윈 무릎" · "아랫배임으로"). AI 가 채팅에서 확인해 달라고 짚지만, 고치는 길은 장면 카드 "자막" 뿐

- 대화 패널 폭이 새 판이 나올 때 한 번 좁아졌다 (c2 캡처, 인스펙터가 최소 폭). 판을 오가도 다시 재현 안 됨
