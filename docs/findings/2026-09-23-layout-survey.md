## 우선순위 재정렬

가장 큰 갭은 2분할이 아니라 **3번 — 이미지가 소스인 장면**이다.

`Scene.source` 가 `{ videoId, in, out }` 이라 영상만 가정한다. 그런데 실제로는
검은 배경에 골격 그림을 띄우고 그 위에 원·화살표·자막을 얹는 장면이 자주 나온다.
이건 오버레이가 아니라 **장면 자체가 이미지**다.

### 제안 (증거 순)

```ts
// 1순위 — 5편 중 2편
Scene.source:
  | { kind: 'video', videoId, in, out }
  | { kind: 'image', assetId, durationSec }

// 2순위 — 5편 중 3편. payload 를 템플릿 spec.json 에 확정
Overlay.kind 'circle' payload: { color: 'red' | 'yellow', rx, ry }
Overlay.kind 'arrow'  payload: { color: 'red', angle, length }

// 3순위 — 5편 중 2편. 이미 slot:'top' 이 있으니 렌더만 검증
Caption.slot 'top'   (Before / After 라벨)

// 4순위 — 5편 중 3편. 1단계 리프레이밍과 함께
Scene.reframe 키프레임 보간 (줌 · 클로즈업)

// 5순위 — 5편 중 1편
Scene.layout 'splitV' + Scene.sources[]
Overlay.kind 'mark' payload: { symbol: 'o' | 'x' }

// 보류 — 5편 중 1편, 장식성
장식 손글씨 텍스트 (별도 폰트 필요)
```

## 이 조사가 실제로 막은 것

조사 전 계획은 `Scene.layout` 과 `Scene.sources[]` 를 먼저 넣는 것이었다.
그대로 했으면 5편 중 1편에만 쓰이는 기능을 코어 스키마에 먼저 박고,
5편 중 2편에 쓰이는 이미지 소스는 그 다음에 또 스키마를 고쳐야 했다.

전작이 망한 방식이 정확히 이것이다 — 관측 없이 자료구조를 정하고, 나중에 못 고쳐서 품질이 막힘.
**스키마를 바꾸기 전에 5편을 본다**를 규칙으로 굳힌다.
