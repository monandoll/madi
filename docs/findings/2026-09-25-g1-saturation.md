## 2. 두 번째로 죽은 가설 — "점유·채움이 높으면 덩어리다"

표본 단위로 `점유 >= 0.60 && 채움 >= 0.70` 인 비율:

| 영상 | 비율 |
|---|---|
| 공개본 6편 | 0% |
| `8DF9jrxQM4U` · `lzDW-9ITfWU` | 4% |
| `59HP4jxLFeA` | 12% |
| `L469kzZZe1E` | **21%** |
| `xaUpqHAQjo4` | **42%** |
| `6U6Qp35FQaM` | 75% |

기존 "측정 불가 20% 초과 → 판정 불가" 기계에 그대로 태우면
**크리에이터 본인 영상 2편(`L469kzZZe1E` 21%, `xaUpqHAQjo4` 42%)이 판정 불가가 된다.**

임계값을 42% 와 75% 사이로 올리면 통과는 하지만, 그건 **양쪽 n=1 에 맞춘 것**이다.
근거가 아니라 곡선 맞추기다. `AGENTS.md §8` 이 금지한 그것이다.

## 3. 실제로 렌더해 보니 — 나쁜 건 맞다. 그런데 G1 탓이 아니다

`6U6Qp35FQaM` 을 리프레임해 렌더했다. 결과는 **손 클로즈업**이다. 쓸 수 없는 화면이다.

원인은 G1 의 오판이 아니라 **원본이 이미 극단적 클로즈업**이라는 것이다.
16:9 원본 자체가 등 위의 손을 꽉 채워 잡은 화면이고, 거기서 9:16 을 잘라내면 손만 남는다.

**G1 의 답은 맞다.** G1 이 묻는 건 "사람 키" 가 아니라 **화면 점유 높이**다
(`AGENTS.md §8`: 마스크 상자 높이 **÷ 프레임 높이**). 마스크가 위아래에 동시에 닿으면
점유 높이는 1.0 이고, 그게 사실이다. 피사체는 실제로 크다.

**그리고 이 영상은 이미 잡히고 있다** — `G2` 가 `판정 불가`(`subjectAlreadyCropped`)를 낸다.
원본에서 이미 위아래가 다 잘려 있어 "우리가 새로 잘랐는가" 를 물을 수 없기 때문이다.
`AGENTS.md §8` 대로 통과로 적히지 않고 사용자에게 이유와 함께 보인다.

## 4. 그래서 한 것 — 판정은 그대로, 사실만 리포트에 남긴다

`Measurement.heightSaturatedCount` 를 추가했다. 마스크가 크롭 위·아래에 **동시에** 닿아
점유 높이가 1.0 으로 포화된 표본 수다.

| 영상 | 포화 | 판정 |
|---|---|---|
| `uw1aUHnMfo8` | 0/40 | G1 통과 |
| `xaUpqHAQjo4` (공개본) | **24/40** | G1 통과 |
| `6U6Qp35FQaM` | **40/40** | G1 통과 · **G2 판정 불가** |

**이 수로 통과를 막지 않는다.** 막으면 크리에이터 본인 영상이 막힌다.
"높이 1.0 은 포화된 값" 이라는 사실만 `Output.reviewReport` 로 넘어가,
나중에 사람이 볼 때 오해하지 않게 한다.
