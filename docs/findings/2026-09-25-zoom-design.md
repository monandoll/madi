### 읽히는 것

1. **확대 필요량은 촬영 방향이 아니라 카메라 거리가 정한다.**
   세로 두 편이 2.25 · 2.31 로 가장 크고, 가로는 1.03~1.34 다.
   세로로 찍어서 확대가 필요한 게 아니라 **멀리서 찍어서** 필요하다.
   (두 세로 영상 다 인물이 멀다 — 헬스장 전경 · 전신 스트레칭)

2. **마스크 끊김은 배경이 정한다.** `IMG_6022` 만 28% 끊기고 나머지 6편은 **0/60** 이다.
   끊기는 쪽은 기구 · 거울 반사 · 2인 겹침 · 핸드헬드다.
   `docs/shooting.md` 의 "배경은 단색 벽" 규칙이 여기에 그대로 걸린다.

3. **무게중심이 크게 튀는 건 2분할·클로즈업이다** (0.228 · 0.283).
   나머지는 0.017~0.048. 0.5초 사이에 화면의 28% 를 움직이는 경우가 있다 — 스무딩 설계의 입력.

## 2. 확대 상한 — 소스 해상도가 정한다

```
배율 1 크롭 폭(px) = min(소스 폭, 소스 높이 × 9/16)
업스케일 배수 U(zoom) = 출력 폭(1080) ÷ (배율 1 크롭 폭 ÷ zoom)
무손실 최대 배율 = 배율 1 크롭 폭 ÷ 1080
```

`madi-spike zoomtest` 실측:

| 원본 | 배율 1 크롭 폭 | `U(1.0)` | 무손실 최대 배율 |
|---|---|---|---|
| 세로 4K 2160x3840 | 2160px | 0.50 | **2.00** |
| 세로 1080p 1080x1920 | 1080px | 1.00 | **1.00** |
| 세로 608x1080 | 608px | **1.78** | 0.56 |
| 가로 4K 3840x2160 | 1215px | 0.89 | **1.13** |
| 가로 1080p 1920x1080 | 608px | **1.78** | 0.56 |

★ **가로 1080p 는 9:16 으로 뽑는 순간 이미 1.78배 업스케일이다.** 확대를 하기 전에.
  9:16 크롭 폭이 608px 뿐이라서다. 확대 여력이 **음수**다.

### 상한을 어디에 두나 — 눈으로 정했다

`out/zoomtest/zoom_*.png` 를 3배로 확대해 나란히 봤다 (세로 4K, 같은 화각):

| 업스케일 | 눈에 보이는 것 |
|---|---|
| 1.00 (배율 2.00) | 또렷하다. 조명 띠 · 거울 모서리가 선명 |
| 1.25 (배율 2.50) | 미세하게 무르다. 나란히 놓아야 보인다 |
| 1.50 (배율 3.00) | **눈에 띄게 뭉갠다.** 기구 디테일이 번진다 |

→ **`U_max = 1.25`** 로 제안한다.

⚠ **평균 |라플라시안| 선명도 지표는 쓰지 못했다.** 소스를 반으로 줄인 대조군이
  오히려 "더 선명" 하게 나왔다(-19%). 다운스케일 후 업스케일이 만드는 에일리어싱을
  이 지표가 디테일로 착각한다. **숫자를 버리고 눈으로 정했다고 적는다.**

### 원본별 허용 배율 vs 필요 배율

| 원본 | 필요 배율 | `U_max=1.25` 허용 | |
|---|---|---|---|
| 세로 4K (`IMG_6022`) | 2.25 | **2.50** | ✅ 여유 있음 |
| 세로 608x1080 (`NOCXAZE8XdQ`) | 2.31 | 0.70 | ❌ 확대 불가 |
| 가로 1080p (매트 바닥) | 1.27~1.34 | 0.70 | ❌ 확대 불가 |
| 가로 1080p (서 있는 전신) | 1.03 | 0.70 | ❌ 확대 불가 |
| 가로 1080p (도수치료) | 0.72 (축소) | — | ✅ 확대 불필요 |

**4K 로 찍으면 2.5배까지 확대할 수 있고, 1080p 로 찍으면 확대할 수 없다.**

이건 촬영 규칙에 넣을 근거다 — 다만 크리에이터 촬영 사양을 확인한 뒤에 넣는다.

### G1 과는 다른 이야기다

확대는 **미학 목표**(`targetSubjectHeightRatio` 0.72)를 맞추기 위한 것이고,
**하드 게이트 G1 은 0.55** 다. 가로 원본은 확대 없이도 0.538~1.000 이라 G1 을 대체로 통과한다.
확대가 **필수**인 건 사람 높이가 0.31~0.32 인 세로 두 편이다.

## 3. 스키마 — **바꿀 필요가 없었다**

`ReframeTrack.Keyframe.rect: NormRect` 가 **위치와 배율을 이미 같이 담는다.**
`rect` 는 "원본의 어느 영역을 보여줄지" 이고, 영역이 작아지면 그게 곧 확대다.

```
zoom = (배율 1 크롭 폭) ÷ (rect 의 픽셀 폭)
```

`Renderer.reframeTransform` 이 이미 `scale = max(출력폭/크롭폭, 출력높이/크롭높이)` 로 처리한다.

### 렌더로 확인했다

`spike/zoom.json` — `IMG_6022` 2~14초에 배율 2.25 고정 크롭(`w=h=0.4444`).

| | 분할 마스크 점유 |
|---|---|
| 원본 t=4.0 | 0.046 |
| 확대본 t=2.0 (같은 순간) | **0.144** (3.1배) |

눈으로도 확인했다 — 확대본에서 두 사람이 화면을 채운다.

→ **배율을 위해 코어 스키마를 고치지 않는다.** 필요한 건 상한 규칙과 **보간**이다.

## 4. 설계가 바뀐 지점 — 필요 배율은 "가장 큰 덩어리"로 계산한다

`IMG_6022` 에서 확대 후 마스크 **상자 높이**는 0.349 → 0.443 (1.27배) 밖에 안 올랐다.
점유는 3.1배 올랐는데도.

원인: 이 영상의 마스크는 **조각나 있다**. 덩어리가 0~3개로 오가고, 거울 반사까지 섞인다.
전체 bbox 는 조각과 반사를 다 감싸서 "사람 높이" 가 아니다.

→ **필요 배율은 전체 bbox 가 아니라 `maskComponents` 의 가장 큰 덩어리로 계산한다.**
  `maskBox` 는 G1 측정용으로만 쓴다.

⚠ 그래도 `IMG_6022` 는 리프레이밍 자동화의 **하한 사례**다. 28% 미검출 · 조각난 마스크에서는
  어떤 규칙을 써도 안정적인 추적이 안 된다. 촬영 규칙(단색 배경 · 인물 70%)이 왜 필요한지를
  보여주는 증거로 회귀 세트에 남긴다.

## 5. 정한 것

1. 확대는 `ReframeTrack.rect` 크기로 표현한다. **스키마 변경 없음**
2. `U_max = 1.25` (업스케일 배수 상한). 근거는 눈으로 본 것 — 1.00 또렷 / 1.25 미세 / 1.50 뭉갬
3. 최대 배율 = `배율 1 크롭 폭 ÷ 1080 × 1.25`. 원본 해상도마다 다르다
4. 필요 배율이 상한을 넘으면 **상한에서 자르고 모자란 양을 리포트에 남긴다.** 조용히 넘기지 않는다
5. 필요 배율은 **가장 큰 마스크 덩어리**로 계산한다 (전체 bbox 아님)

## 6. 아직 안 정한 것

- 세로 중심 (지금은 무게중심 한 점. 확대하면 세로도 골라야 한다)
- 시간축 스무딩 (0.5초 사이 최대이동 0.283 을 어떻게 다룰지)
- 마스크가 끊긴 구간의 보간 (28% 끊기는 영상이 실재한다)
