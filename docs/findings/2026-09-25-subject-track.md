# SubjectTrack → 키프레임 → 되쓰기 → 렌더 보간 — 실측 (2026-09-25)

1단계 3번. 파이프라인 전체를 잇고 회귀 세트 8편에서 G1 · G3 을 쟀다.

```
프레임(0.5s) → 분할 마스크 → 덩어리 → IoU 이어가기 → 배율·중심 → 빈 구간 채우기
             → 스무딩(0.4s) → 키프레임 → Composition 되쓰기 → Renderer 프레임별 변환
```

도구: `madi-spike reframe <영상> [--until N] [--render] [--keys]`

## 2. `maskComponents` 하한 0.5% 가 사람을 버리고 있었다

IMG_6022 의 입력없음이 처음에 48% 로 나왔다. 이전 측정(`track`, 27.5%)과 달랐다.

원인: `maskComponents(minCoverage:)` 기본값 **0.005**. 4K 세로로 멀리서 찍으면
1등 덩어리가 프레임의 **0.6~1.7%** 뿐이라 하한 바로 위에 있고, 절반이 걸러졌다.

| 하한 | IMG_6022 (4K) | IMG_6022_1080 | `uw1aUHnMfo8` (깨끗) |
|---|---|---|---|
| 0.005 (이전) | 48% | 60% | 0% |
| 0.001 | **30%** | **42%** | 0% |
| 0.0005 | 30% | 42% | 0% |

→ 기본값을 **0.0005** 로 내렸다 (`SubjectTrackBuilder.defaultMinCoverage`).
깨끗한 원본에 손해가 없고 어려운 원본에서 18%p 를 되찾는다.

⚠ 그래도 IMG_6022 는 30% 로 20% 기준을 넘는다. **판정 불가는 그대로다.**

### 해상도 대가는 실측된다

같은 영상, 같은 하한에서 4K 30% vs 1080p **42%**.
1080p 로 줄이면 분할 마스크가 12%p 더 끊긴다. "1080p 도 1급" 이지만 **등급이 같지는 않다.**

## 3. 세로 중심 규칙 — **아직 못 정한다**

`boxCenter`(상자 중심)와 `massCenter`(무게중심)를 같은 원본에서 나란히 쟀다.

기본 설정(목표 0.72)에서는 **8편 중 7편이 완전히 동일**했다. 배율이 1 에 머물러
크롭이 전체 높이를 쓰기 때문에 세로에 고를 자유가 없다.

배율이 실제로 걸리는 IMG_6022(4K, 배율 2.2~2.5)에서만 차이가 났다:

| 목표 | 규칙 | 잘림 | 위잘림 | 아래잘림 | G3 최대이동 |
|---|---|---|---|---|---|
| 0.72 | boxCenter | 0.053 | 0.000 | **0.006** | 0.0203 |
| 0.72 | massCenter | 0.055 | 0.000 | **0.008** | 0.0211 |
| 0.95 | boxCenter | 0.074 | 0.000 | **0.002** | 0.0135 |
| 0.95 | massCenter | 0.076 | 0.000 | **0.004** | 0.0128 |

방향은 `boxCenter` 가 낫다 — `massCenter` 는 아래(발)를 2배 더 자른다.
서 있는 사람은 무게중심이 상자 중심보다 위에 있어 크롭이 위로 밀리기 때문이다.

**하지만 차이가 상자 높이의 0.2~0.4% 다. 결정적이지 않다.**
→ 기본값은 `boxCenter` 로 두되 **`추측한 값` 목록에 남긴다.**
  깨끗한 세로 원본이 들어오면 다시 잰다. 코드에는 두 규칙이 다 있고
  (`ReframePlanner.VerticalAnchor`) `reframe` 을 돌리면 두 줄이 같이 나온다.

## 4. 찾은 버그 — `NormRect.y` 기준이 반대였다

확대가 걸린 IMG_6022 를 렌더했더니 **마지막 칸들이 천장**이었다.

원인을 추측하지 않고 쟀다. 고정 크롭 `{x:0.42, y:0.0, w:0.158, h:0.5}` 로 1초를 렌더했다.

| | 결과 |
|---|---|
| 수정 전 | `y = 0.0` 이 **윗절반** (머리·어깨) — `frames/2026-09-25-y기준-버그-y0가윗절반.jpg` |
| 수정 후 | `y = 0.0` 이 **아랫절반** (다리·발) — `frames/2026-09-25-y기준-수정-y0가아랫절반.jpg` |

분할 마스크 · 무게중심 · 자막 레이아웃(CoreText · CALayer)은 전부 **아래 기준**인데
AVFoundation 합성 좌표계만 **위 기준**이다. 그 차이를 아무도 변환하지 않고 있었다.

**0단계에는 드러날 수 없었다.** 크롭이 항상 전체 높이(`h = 1`)여서
`1 - y - h == y` 였기 때문이다. 확대를 넣는 순간 바로 나왔다.

→ 기준을 **아래**로 통일하고 `Renderer.reframeTransform` **한 곳에서만** 뒤집는다.
  `NormRect` 주석과 테스트(`NormRect.y 는 아래에서 잰다`)로 못을 박았다.

재현용 고정 크롭 컴포지션을 `spike/ytest.json` 에 남겼다.
`madi-spike render spike/ytest.json out/ytest/y0.mp4` 로 다시 확인할 수 있다.

## 5. 되쓰기와 렌더 보간

- `reframe.mode == .auto` 인 장면을 `.keyframes` 로 바꾸고 키프레임을 채운다
- **JSON 왕복이 같다** — 테스트로 지킨다. 안 그러면 재현 가능성이 깨진다 (`AGENTS.md §1-8`)
- 키프레임 시각은 **장면 로컬 출력 초**다. 배속을 반영한다
- `Renderer` 가 `setTransformRamp` 대신 **출력 프레임마다 변환을 다시 준다.**
  화면 배율이 `1 / 크롭폭` 이라 크롭에 선형이 아니고, 램프는 행렬을 선형 보간하므로
  확대 구간에서 어긋난다. 단계 수 상한 1200

프레임 시트 (`AGENTS.md §14`):
- `frames/2026-09-25-reframe-uw1aUHnMfo8.jpg` — 16:9 → 9:16, 좌우 팬
- `frames/2026-09-25-reframe-IMG_6022-판정불가.jpg` — 4K 세로, 배율 2.2~2.5
