# 자막 분절을 공개본에 맞춰 봤다 — 그리고 내 `pauseSec` 측정이 틀렸다 (2026-09-26)

전사가 붙었으니 분절을 **쌤 실제 자막과 대조**할 수 있게 됐다.

```
낱말(WhisperKit) → CaptionSplitter → 우리 덩어리
번인 자막(OCR)                      → 쌤 덩어리
경계가 ±0.3초 안에서 겹치면 "같은 자리에서 끊었다"
```

도구: `madi-spike splittest`.

---

## 1. ⚠ 정정 — `pauseSec` 0.30 은 잘못 잰 값이다

직전 기록(`2026-09-26-whisperkit.md §3`)에서 이렇게 적었다.

> 끊은 자리 쉼 중앙 0.26~0.44 / 안 끊은 쉼 중앙 0.000 → `pauseSec` = 0.30

**틀렸다.** 같은 영상의 낱말 사이 간격을 직접 세어 보니:

```
n=42  중앙 0.000  p75 0.000  p90 0.000  최대 0.600  · 0.30 이상 단 2개
```

`CaptionSplitter` 가 실제로 보는 값(`word.start - 직전 word.end`)은 **거의 전부 0** 이다.
쉼으로 끊으려 해도 끊을 자리가 없다.

두 가지를 잘못 봤다:

1. **`capsync` 의 "끊은 자리 쉼" 이 낱말 간격이 아니었다.** OCR 덩어리 창에 걸리는
   낱말만 모은 뒤 그 바깥의 낱말과 비교해서, 창 밖으로 밀려난 낱말들이 만든 **인위적인 간격**을 쟀다
2. **OCR 덩어리 사이의 0.25초는 쉼이 아니라 표본 간격이다.** 초당 4프레임으로 읽으니
   덩어리 경계가 0.25초 격자에 걸린다. 쌤이 0.25초 쉰 게 아니다

→ `pauseSec` 을 스키마에서 **뺐다.** 쓰지 않는 값을 남겨 두지 않는다.
→ `maxDurationSec` 3.0 은 OCR 덩어리 **길이**를 잰 것이라 이 오류와 무관하다. 그대로 둔다.

## 2. 분절을 막고 있던 건 규칙이 아니라 **전사 품질**이었다

`base` 모델의 한국어 오독이 심하다.

| 원문 (쌤 자막) | `base` | `small` |
|---|---|---|
| 사람들은 | **그럼 들은** | 사람들은 |
| 모르시더라구요 | **모르시도** | 모르시더라고요 |
| 베개를 | **100일을** | 100이를 |
| 매일 30번씩 | **서로머시에** | 매일 서른 번씩 |

텍스트가 다르면 경계 일치를 재는 것 자체가 무의미하다.
같은 규칙 · 같은 영상에서 **모델만 바꿨더니**:

| 모델 | 크기 | 데운 뒤 속도 (18.5초 영상) | 경계 일치 |
|---|---|---|---|
| `base` | 141MB | 2.5초 | **4/13** |
| `small` | 484MB | 3.6초 | **9/13** |
| `large-v3` | 2.9GB | 25.2초 | 측정 실패 (아래) |

→ 기본 모델을 **`small`** 로 바꿨다. 속도 차이가 1.1초뿐인데 품질 차이가 크다.

### `large-v3` 는 지금 쓸 수 없다

- **2.9GB.** `.dmg` 에 넣기도, 첫 실행에 받기도 부담이다
- 데운 뒤에도 **25.2초** — 18.5초 영상에 1.4배 실시간이다. "편집 10분" 에 불리하다
- `splittest` 경로(전사 + Vision OCR 동시)에서 **ANE 오류로 계속 실패**한다
  (`e5rtError … call failed`). 전사만 단독으로 돌리면 된다

3단계 모델 결정 때 쓸 수 있게 숫자를 남긴다. `medium` 은 아직 안 쟀다.

## 3. 규칙은 시간이 아니라 **문법**에 있다

쌤 자막 경계를 읽으면 규칙이 보인다.

```
전 골반교정 할 때,   /  이거 무조건 하는데  /  사람들은 생각보다
이거 모르시더라구요  /  7자 다리를 한 상태에서  /  일자로 천천히 일어나주시고
```

`…할 때,` `…하는데` `…생각보다` `…더라구요` `…상태에서` `…주시고` —
**연결어미 · 종결어미 · 부사격 조사**다. 쉼이 아니라 구문 경계에서 끊는다.

`CaptionSplitter` 를 그렇게 바꿨다:
1. 낱말을 담다가 **최소 글자 수(`minCharsBeforeBreak`)를 넘긴 뒤 구문 경계가 나오면 끊는다**
2. 상한(15자)을 넘기면 **뒤로 되짚어** 가장 가까운 구문 경계에서 끊는다
3. 낱말 안에서는 절대 끊지 않는다

### `minCharsBeforeBreak` 훑기 — 같은 3편 기준

| 값 | 경계 일치 | 우리만 (군더더기) |
|---|---|---|
| 9 | 25/52 (48%) | 22 |
| **6** | **30/52 (58%)** | **21** |
| 5 | 28/52 (54%) | 26 |
| 4 | 32/52 (62%) | 28 |

4 가 일치는 가장 높지만 군더더기 경계가 늘어 **과분절**이 된다.
6 이 일치 대비 군더더기가 가장 낫고, 결과 덩어리 중앙값(11~12자)이
쌤 실측(9~11자)에 가장 가깝다. **6 으로 정했다.**

이름을 `targetChars` → `minCharsBeforeBreak` 로 바꿨다.
6 은 목표가 아니라 **하한**이다 — 결과 중앙값은 11~12자다. 이름이 값을 속이면 안 된다.

## 4. 결과 (공개본 6편, `small` · `minCharsBeforeBreak` 6)

| 영상 | 우리 덩어리(중앙) | 쌤 덩어리(중앙) | 경계 일치 | G5 | G6 |
|---|---|---|---|---|---|
| `8DF9jrxQM4U` (20초) | 14 (13) | 14 (11) | 9/13 | 통과 | 통과 |
| `EDpBGkaNJmU` | 15 (11) | 15 (11) | 9/14 | 통과 | 통과 |
| `59HP4jxLFeA` | 17 (11) | 15 (11) | 9/14 | 통과 | 통과 |
| `L469kzZZe1E` | 22 (12) | 25 (9) | 12/24 | 통과 | 통과 |
| `UzemW44yzSo` | 19 (11) | 22 (9) | 10/21 | 통과 | 통과 |
| `RnP7b0JFWj4` | 23 (12) | 27 (9) | 14/26 | 통과 | 통과 |

- **G5 · G6 은 6편 전부 통과.** G6 최대 오차 0.000초 —
  자막이 낱말에서 나오니 당연하다. **G6 은 분절이 낱말 시각을 안 건드린다는 확인이지
  "쌤처럼 끊었다" 는 증거가 아니다**
- **경계 일치는 50~69%, 대략 60%다.** 절반 조금 넘게 같은 자리에서 끊는다
- 덩어리 수는 쌤보다 **적다** (우리가 조금 더 길게 담는다)

### 60% 를 어떻게 읽을 것인가

남은 40% 가 전부 틀린 게 아니다. 세 가지가 섞여 있다:

1. **전사 오독** — `small` 도 "틀어싱", "100이를" 을 낸다. 틀린 텍스트는 경계도 틀린다
2. **OCR 경계 오차 ±0.25초** — 판정 허용치가 0.3초라 경계가 아슬아슬하게 빗나간다
3. **진짜 분절 차이** — 쌤이 더 잘게 끊는다 (중앙 9자 vs 우리 11~12자)

1·2 를 걷어내지 않은 숫자다. **60% 를 "분절 정확도" 로 읽으면 안 되고
"현재 파이프라인 전체의 재현율" 로 읽어야 한다.**

## 5. 남은 것

- `medium` 모델 미측정. 3단계 모델 결정 때 같이
- 구문 경계 목록(`clauseEndings`)은 **쌤 자막을 읽고 손으로 적은 것**이다.
  형태소 분석기를 쓰지 않는다 (외부 의존성). 놓치는 어미가 있을 수 있다
- `minCharsBeforeBreak` 6 은 **3~5편으로 고른 값**이다. 촬영본이 들어오면 다시 훑는다
- ⚠ WhisperKit 이 모델을 **`~/Documents/huggingface/`** 에 받는다.
  사용자 문서 폴더를 쓰는 건 제품으로 나갈 수 없다 — 3단계에서 캐시 경로로 옮긴다
