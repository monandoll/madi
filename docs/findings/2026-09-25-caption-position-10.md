# 자막 위치 실측 — 공개 숏폼 10편 (2026-09-25)

`docs/findings/2026-09-25-layout-survey-10.md` 가 "자막 세로 위치가 편마다 달라 보이는데
숫자로 확정하지 못했다" 고 남긴 숙제다. 측정 도구를 고치고 10편을 다시 쟀다.

---

## 1. 도구를 먼저 고쳤다 — "검은 외곽선이 있는 흰 글자"

이전 도구는 자막 픽셀을 **흰색(r,g,b > 230)** 으로만 판정했다.
이 채널 영상에는 흰 벽 · 흰 양말 · 밝은 피부가 널려 있어서 그걸 자막으로 잡았고,
10편 중 절반의 측정이 엉뚱하게 나왔다.

자막에만 있는 성질은 **검은 외곽선**이다. 글자 획은 얇아서, 획 안의 어느 흰 픽셀에서든
가까운 거리 안에 검은 픽셀이 **양쪽으로** 있다.

- 세로획 → 왼쪽·오른쪽에 검정
- 가로획 → 위·아래에 검정
- 흰 벽 → 어느 방향으로도 검정 없음 ✗
- 흰 양말 → 가운데가 탐색 반경보다 두꺼워서 통과 못 함 ✗ (가장자리 몇 픽셀만 통과하는데
  그건 "한 행에 최소 몇 픽셀" 조건에서 걸러진다)

탐색 반경은 프레임 높이의 1.2% (1920 에서 23px). 실측 외곽선 6px + 획 8px 에 여유를 뒀다.

`tools/measure.mjs` 의 `makeGlyphTest` 와 `StillRenderer.scanStrokes` 가 **같은 정의**를 쓴다.

### 같이 고친 것 — 탐색 창

자막을 화면 **아래 40%** 에서만 찾고 있었다. 그 가정 때문에 위쪽에 자막을 놓는 편 3개를
통째로 놓쳤다(검출 0장). 아래 **65%** 로 넓혔다.
넓혀도 오검출이 늘지 않는 이유는 글자 판정이 외곽선을 요구하기 때문이다.

### 회귀 확인 — 원본이 여전히 통과한다

**숫자가 고치기 전과 한 자리도 다르지 않다.** 폭만 배경 흰색이 빠져 정확해졌다.
`madi-spike stems` 도 동일 (yt_15s 5.31 / yt_11s 5.46 / native_015 8.02 — 전부 그대로).

### 글자 크기는 확정해도 된다

10편 전부 **3.39% ~ 3.65%**, 중앙값은 8편이 3.54~3.59% 다.
`short.v1.json` 의 `inkHeightRatio` 0.0359 는 **10편으로 뒷받침된다.**

### 자막 위치는 확정할 수 없다 — 세 무리로 갈린다

| 무리 | 아래끝 | 편수 | 그 편들의 내용 |
|---|---|---|---|
| A | **0.235** | 3 | 앉아서 말하는 상반신 (`EDpBGkaNJmU` `59HP4jxLFeA` `8DF9jrxQM4U`) |
| B | **0.292~0.314** | 3 | 서 있는 전신 (`UzemW44yzSo` `L469kzZZe1E` `nCshtY04NiY`) |
| C | **0.469~0.483** | 4 | 바닥·침대의 하체 클로즈업 (`RnP7b0JFWj4` `lzDW-9ITfWU` `Wp7dWPpiFew` `xaUpqHAQjo4`) |

**편 안에서는 거의 완벽하게 고정**이다 (`8DF9jrxQM4U` 는 12프레임 전부 0.2354).
**편 사이에서는 0.235 에서 0.483 까지 벌어진다.** 프레임 높이의 25% 차이다.

눈으로도 확인했다 — `frames/2026-09-25-caption-position-clusters.jpg`.
측정값 위치에 빨간 선을 그어 두 프레임에 겹쳤고, 선이 자막 아래끝에 정확히 놓인다.

→ **`short.v1.json` 의 `inkBottomRatio` 0.2352 는 A 무리 값이다.
  `measured` 를 true 로 올릴 수 없다.** 값 하나로 뭉개면 C 무리 영상에서
  자막이 화면 25% 아래에 찍힌다.

### 가설: 자막이 피사체를 피해 올라간다 — ⚠ 미검증

무리와 내용이 정확히 갈린다. A 는 상반신, C 는 바닥의 하체다.
C 편들은 동작이 화면 아래쪽에서 일어나므로 자막을 올려 가리지 않게 한 것으로 보인다.

이건 **`AGENTS.md §8 G7`(자막 가림)이 말하는 바로 그 규칙**이다.
지금 G7 은 "자막 박스가 어깨선 위 관절을 덮지 않음" 인데, 실제 크리에이터는
덮지 않기 위해 **자막을 움직인다.**

→ 스타일이 위치를 하나로 박으면 안 되고, **기본 위치 + 피사체를 피해 올리는 규칙**이어야 한다.
  다만 이건 10편의 내용 분류에서 나온 **가설**이다. 확정하려면 각 편의 피사체 위치를 재서
  자막 위치와의 관계를 봐야 하는데, 사람 감지가 바로 그 C 무리에서 실패한다
  (`docs/findings/2026-09-25-pose-detection-spike.md`). 닭과 달걀이다.

## 3. 보조 문구는 본문에 붙어 다닌다 — 상대 위치가 맞다

본문 아래끝 − 보조 베이스라인:

| 영상 | 간격 | | 영상 | 간격 |
|---|---|---|---|---|
| `EDpBGkaNJmU` | 0.0333 | | `L469kzZZe1E` | 0.0412 |
| `59HP4jxLFeA` | 0.0307 | | `nCshtY04NiY` | 0.0328 |
| `8DF9jrxQM4U` | 0.0333 | | `RnP7b0JFWj4` | 0.0396 |
| `UzemW44yzSo` | 0.0307 | | `lzDW-9ITfWU` | 0.0344 |

본문 위치가 0.235~0.483 으로 벌어지는 동안 **간격은 0.031~0.041 로 붙어 있다.**

(`Wp7dWPpiFew` 0.100 · `xaUpqHAQjo4` 0.103 은 제외했다. 이 두 편은 **영문 보조 자막이 아예 없어서**
노랑으로 잡힌 게 배경이다. 앞선 조사에서 확인한 사실과 일치한다.)

→ **제안: `secondary.baselineBottomRatio`(절대) 를 `secondary.baselineOffsetRatio`(본문 대비 상대)
  로 바꾼다.** 본문이 움직이면 보조도 같이 움직여야 하는데, 지금 스키마는 따로 논다.
  0단계 스파이크는 A 무리 1편만 다뤄서 이 문제가 드러나지 않았다.

**고치지 않았다.** 스키마 변경이라 사람이 정할 일이다.
