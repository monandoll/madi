## 결론부터 — 1순위가 또 뒤집혔다

이전 조사의 1순위는 **"이미지가 장면 자체인 경우"** 였고,
`enum Source { case video / case image }` 로 코어 스키마를 고치자는 제안이었다.

**10편에서 그런 장면은 0편이다.**

해부학 그림과 사진은 4편에 나오는데, **전부 영상 위에 얹은 카드**다.
화면을 꽉 채우지 않고, 카드 바깥으로 영상이 계속 보인다.
필요한 건 `Source.image` 가 아니라 **`Overlay.kind == .image` 의 payload 정의**다.
그건 이미 있는 kind 이므로 **코어 스키마를 고칠 필요가 없다.**

5편에서는 2편이 "이미지 장면" 으로 보였는데, 6장씩만 봐서 카드 바깥의 영상을 놓쳤다.
편당 10장으로 늘리고 원본 해상도로 보니 카드였다.

> 5편에서 1편 보고 정하지 말라는 교훈을 얻었고, 10편에서 5편 보고 정하지 말라는 교훈을 얻었다.
> **구현 직전에 한 번 더 세는 절차가 실제로 두 번 다 값을 했다.**

## 덤으로 나온 것

### 1. 영문 보조 자막이 없는 편이 2/10

`Wp7dWPpiFew` 와 `xaUpqHAQjo4` 에는 노란 영문 줄이 아예 없다.
`Caption.secondary` 가 `Optional` 이라 스키마는 문제없지만,
**"보조 문구는 항상 있다" 고 가정한 코드가 있으면 안 된다.**

### 2. 자막 세로 위치가 편마다 달라 보인다 — ⚠ 미측정

격자 시트에서 자막이 화면 아래 끝에 붙은 편과 눈에 띄게 위에 있는 편이 갈린다.
특히 `Wp7dWPpiFew` · `xaUpqHAQjo4` 가 높다.

**숫자로 확정하지 못했다.** `tools/measure.mjs` 가 흰 벽 · 피부를 자막으로 잡아
배경이 다양한 프레임에서는 못 쓴다 (10편 중 절반이 측정 실패하거나 엉뚱한 값).
`short.v1.json` 의 `inkBottomRatio` 0.2352 는 `EDpBGkaNJmU` 한 편에서 나온 값이다.

→ **스타일 값을 여러 편으로 확정하려면 측정 도구부터 고쳐야 한다.**
  자막은 "외곽선이 있는 흰 글자" 라는 점을 이용해 배경과 구분하는 쪽이 맞다
  (흰 픽셀 바로 바깥에 검은 테두리가 있는가).

### 3. 2줄 자막 프레임을 드디어 찾았다

`nCshtY04NiY` 에 "2. 허벅지 안쪽을 / 바깥쪽으로 돌리기" 가 2줄로 나온다.
`short.v1.json` 의 `lineGapRatio` 는 지금 **근거 없는 1.35** 다
(`docs/findings/2026-09-25-coretext-caption-measurement.md §7`).
이 프레임으로 잴 수 있다. 위 2번 도구 문제와 같이 처리한다.

### 4. 훅 자막은 본문보다 크지 않다 — 해결

`reference/yt_1_5s.png` (720x1280) 가 본문 높이 **3.75%** 로 읽혀 다른 프레임(3.59%)보다
컸는데, 네이티브 1080p 원본에서 같은 시각을 재니 **3.54%** 로 17.0초와 **완전히 같다**
(둘 다 글자 밴드 y 1400..1467).

원인은 720p 다운스케일이다. 글자 바로 위의 밝은 배경(흰 벽 · 팔)이 글자 밴드와 붙어서
한 덩어리로 읽혔다. 1080p 에서는 그 사이에 어두운 행이 남아 분리된다.

→ **훅 자막과 본문 자막은 같은 크기다.** 스타일에 훅 전용 크기를 두지 않는다.
   이 과정에서 측정 도구의 밴드 선택 버그도 같이 고쳤다.
