## 1단계 — 뼈대 · 갤러리 (2026-09-25)

### 시스템 기본값으로 둔 것

거의 전부다. 화면에서 "우리가 정한 값" 은 아래 **커스텀** 목록이 전부이고, 나머지는
SwiftUI 가 주는 그대로다.

| | 쓴 것 |
|---|---|
| 창 구조 | `NavigationSplitView` (사이드바 + 본문 + `inspector`) |
| 사이드바 | `List(selection:)` + `Section` + `Label` + `.badge` |
| 그리드 | `LazyVGrid(.flexible × n)` + `Section` 헤더 |
| 빈 상태 · 접근 불가 | `ContentUnavailableView` |
| 우클릭 | `.contextMenu { } preview: { }` |
| 거르개 | 툴바 `Picker(.segmented)` |

| 글꼴 | 시스템(SF) + `.headline` `.callout` `.caption` 시맨틱 스타일만 |

### 커스텀한 것 (이유)

| 값 | 어디 | 왜 |
|---|---|---|
| 강조색 `#2D6A55` | `Tokens.Palette.accent` | 시스템 강조색은 Mac 마다 다르다. 주요 버튼 색이 기기마다 달라지면 화면 설명이 안 맞는다. 시안이 쓰는 초록으로 고정 |
| 세로 비율 9:16 | `Tokens.Ratio.vertical` | 결과물이 세로 고정이다. 가로 썸네일로 그리면 결과가 가로인 줄 안다 |
| 그리드 칸 바라는 폭 170pt · 최소 4칸 | `Tokens.Size.gridItemIdeal` | 칸 수를 이 값으로 세고 폭은 칸이 나눠 갖는다. 세로 칸이라 한 줄에 적게 놓으면 한 화면에 몇 개 안 보인다 |
| 정보 패널 240/280/360 | `Tokens.Size.inspector*` | 기본 인스펙터 폭이 좁아 9:16 미리보기가 눌린다 |
| 날짜 꼴 `9월 25일` | `Copy.day` | 시스템 한국어 템플릿은 `9. 25.` 를 준다. 묶음 제목으로 읽으면 날짜로 안 보인다 |
| 간격 2/4/8/12/16/20 | `Tokens.Space` | 8pt 격자에 이름만 붙인 것. 새 숫자를 만들지 않았다 |

### 추측한 것 (근거가 시안뿐이거나 없음)

1. **묶음 기준** — 오늘 / 이번 주 / 지난주 / 그 전. 사진 앱을 따랐다.
   실제로 하루 몇 편씩 찍는지 모른다. 하루에 10편이면 "오늘" 이 너무 길어진다
2. **말소리 표시** — `잘 들려요 · 조금 시끄러워요 · 소리가 없어요` 세 단계.
   실제 판단 기준(무음 비율? SNR?)은 개발이 정한다. 화면은 세 단계만 안다
3. **칸에 보여주는 것** — 제목 2줄 + 시각 + 결과물 수.
   제목은 말소리에서 뽑는다고 가정했다. 말소리가 없는 촬영본은 제목이 빈다 —
   지금은 시각으로 대신 보여주게 뒀다
4. **길이 뱃지** — 사진 앱처럼 썸네일 오른쪽 아래. 3분짜리도 `2:56` 한 줄로 들어간다
5. **거르개 3칸** — `전체 · 편집 전 · 결과물 있음`. 시안 그대로다. "이거 이미 만들었나" 를
   푸는 장치라고 봤다

### 물어본 것과 답 (2026-09-25)

1. **설정을 사이드바에 넣을까?** → **넣지 않는다.** 앱 메뉴 `마디 > 설정…` (⌘,) 가 기본 경로다.
   사이드바 맨 아래 스튜디오 이름 줄에 톱니를 붙여 누를 수 있다는 것만 보인다
2. **`바로 숏폼 뽑기` 와 `편집안 열기` 를 둘 다 둘까?** → **하나로 합친다. `숏폼 만들기`.**
   누르면 편집안이 열리고 AI 가 초안을 짜기 시작한다. 실제 영상 만들기는 장면 카드를 본 뒤
   편집안 안에서 한다. **장면 카드를 건너뛰고 영상이 나오는 길은 없다** (`§1-3`, `§10`)
3. **촬영본 지우기** → "삭제" 라는 말을 쓰지 않는다. `목록에서 숨기기` 이고,
   누르면 상태줄이 "사진 앱의 원본은 그대로 있어요" 라고 말한다
4. **1100pt 에서 3칸?** → **4칸.** 세로 칸이라 3칸이면 한 화면에 4~5개밖에 안 보인다.
   칸 수를 직접 세고 `.flexible` 로 폭을 나눠 갖게 바꿨다 (`.adaptive` 는 1440 에서
   오른쪽에 빈 폭을 남겼다)

### 샘플 그림을 둘로 나눴다

촬영본 썸네일이 자막 박힌 완성본 프레임이었다. 원본에는 자막이 없다.
- 촬영본 → `docs/design/sample-frames/` (자막 아래끝 0.235 인 편만 골라 위 70% 만 남김)
- 결과물 → `reference/` (자막 있는 그대로)

미리보기에서 "원본" 과 "만든 것" 이 같아 보이면 안 된다. 3단계 재생 막대에서 특히 그렇다.
위 70% 만 쓰기 때문에 촬영본 썸네일은 실제보다 조금 당겨 보인다 — 공개본에서 자막을 지울
방법이 없어서 생긴 한계다.

## 3단계 — 편집안 상세 (2026-09-25)

화면 셋이 한 창에 같이 있다. **왼쪽 위** 지금 어떻게 생겼나(재생 막대 + 요약),
**왼쪽 아래** 무엇으로 이뤄졌나(장면 목록), **오른쪽** 어떻게 고칠까(대화).

### 시안과 다르게 한 것 — 장면을 **세로 목록**으로

`02-Editor-v2` 는 장면 카드를 가로 띠로 놓았다. 그대로 만들어 1100×700 에서 찍어 보니
**9개 중 2~3개만 보였다.** 편집안을 훑는 게 이 화면의 일인데 훑을 수가 없다.

세로 목록으로 바꾸니 같은 창에서 6~7개가 보이고, 위에서 아래로 읽는 순서가 영상 순서와 같아서
"몇 번째 장면" 을 세기도 쉽다. 카드에 있던 것(번호 · 썸네일 · 역할 · 자막 · 길이 · 버튼)은
그대로 한 줄에 들어간다.

두 크기 스크린샷이 실제로 막은 것이라 기록해 둔다. 1440 만 봤으면 가로 띠로 갔다.

### 지운 것 — "지금 보는 장면" 카드

시안에는 재생 막대 아래에 "지금 보는 장면" 카드가 따로 있었다. 세로 목록에서는 고른 줄이
이미 그 자리다. 같은 것을 두 군데 두면 어느 쪽을 봐야 하는지 묻게 된다.

### 자막 위치를 편집안 정보에 둔 이유

`docs/findings/2026-09-25-caption-position-10.md` — 자막 세로 위치는 **한 편 안에서 고정**이고
(12프레임 전부 같은 값) 편 사이에서만 벌어진다. 그래서 `CaptionSlot` 은 편집안에 하나이고,
"자막 · 아래쪽 · 인물 아래가 비어 있어요" 처럼 **왜 거기인지까지** 한 줄로 보여준다.
장면 줄에는 자막 위치를 두지 않았다 — 두면 장면마다 다르게 할 수 있다는 뜻이 된다.

### 재생 막대에 보이는 자막

미리보기 그림은 크리에이터 공개본 프레임을 그대로 읽는다. **자막을 흉내 내 그리지 않았다**
(design-ai 지침 3). 샘플 편집안은 공개본 한 편(18.5초)을 되짚어 만든 것이라
**장면 줄의 자막과 그 장면 프레임의 자막이 같다.** 아무 프레임이나 붙이면 화면을 보는 사람이
"둘 중 뭐가 맞나" 를 먼저 묻게 된다.

### 상태 6개를 그렸다

| 파일 | 상태 |
|---|---|
| `plan-ready` | 편집안 나옴 · 장면 4번 고른 상태 |
| `plan-editing-caption` | 줄 안에서 자막 고치는 중 |
| `plan-preparing` | AI 가 짜는 중 (단계 목록 · 멈추기 · 칩 잠김) |
| `plan-stuck` | 소리가 없어 자막을 못 만든 경우 — 다음 행동 3개 |
| `plan-unsure-reframe` | 화면 잡기를 **확인 못 한** 경우 (`§8` 판정 불가) |
| `plan-no-ai` | AI 연결 안 됨 — 한 줄만 |

붉은색은 한 군데도 쓰지 않았다. 소리 없음도 AI 미연결도 실패가 아니다 (`§1-6`).

### 추측한 것

1. **편집안 번호** — `편집안 2` 처럼 번호로 부른다. 고칠 때마다 새로 생기고 이전 것을
   지우지 않으므로 (`§1-8`) 툴바 메뉴에서 고를 수 있게 뒀다. 실제로 몇 개까지 쌓이는지는 모른다
2. **줄마다 있는 세 버튼** — `빼기 · 늘리기 · 자막`. 시안에 있던 것 그대로다.
   `늘리기` 가 몇 초 늘리는지는 우클릭 메뉴에서 `1초 늘리기` 로만 말하고 있다
3. **단계 4개** — 받아적기 → 장면 나누기 → 쉬는 구간 찾기 → 화면 잡기.
   실제 파이프라인(`§6`, `§7`)을 사람 말로 옮긴 것이고, 순서와 이름은 개발과 맞춰야 한다
4. **"20초쯤 남음"** — 남은 시간을 아는 단계에만 붙였다. 모르면 안 붙인다

### 고친 것 (확인 뒤, 2026-09-25)

1. **`captionSlot` 을 실제 스키마에 맞췄다.** `rebuild` 를 다시 합치니 `1fa7014` 에 들어와 있었다.
   `.upperBody / .fullBody / .lowerBody` — 값도 이름도 그대로 쓴다
2. **자막 자리 설명에서 위치어와 "빈 곳" 을 뺐다.** "아래쪽 · 인물 아래가 비어 있어요" 는
   기각된 가설이다 (`docs/findings/2026-09-25-caption-position-rule-test.md` — 실제 자막은
   피사체 **위에** 얹혀 있었다). 지금 문구는 `자막 자리 · 상반신 영상` 이고,
   채팅은 "앉아서 말하는 영상이라 자막은 상반신 자리에 뒀어요" 다
3. **1100×700 에서 장면 6개가 안 보였다** (앞선 보고가 틀렸다 — 실제로는 4개 반이었다).
   줄 높이를 1pt 단위로 줄이고 위쪽 높이를 216pt 까지 낮춰 **7개**가 보인다
   (6개는 완전히, 7번째는 걸쳐서)
4. **추천 칩이 오른쪽에서 잘렸다.** 가로 스크롤을 버리고 `FlowLayout` 으로 줄바꿈한다.
   두 크기 모두 다 보인다

### 물어본 것과 답 (2026-09-25)

1. **`만들기` 를 누른 뒤** → 편집안 화면에 **그대로 머문다.** 미리보기 옆이 진행(66% ·
   자막 만들기 → 화면 잡기 → 영상 만들기 · "창을 닫아도 계속 만들어요")으로 바뀌고,
   장면 목록은 흐려지며 읽기 전용이 된다. 툴바는 `멈추기`.
   다 되면 **결과물이 대화에 카드로** 붙고 사이드바 결과물 숫자가 하나 는다
2. **장면 순서** → 끌어서 옮기기 + 채팅 둘 다. `List` 의 기본 이동이라 손잡이를 그리지 않았고,
   목록 제목 옆에 "끌어서 순서를 바꿀 수 있어요" 한 줄을 뒀다
3. **쉬는 구간 자국** → 계속 보여준다. 얇은 줄 + `되돌리기`. 만드는 중에는 되돌리기만 감춘다
4. **자막 여러 덩어리** → 접었을 때 첫 덩어리 + `외 2개`, 고른 줄에서 전부 펼친다.
   영문 보조와 버튼도 고른 줄에만 나온다 — 아홉 줄이 다 펼쳐져 있으면 훑을 수가 없다

### 물어볼 것

1. **자막을 고치면 영문 보조는 어떻게 되나?**
   지금은 본문만 고치게 그려 뒀다. 영문도 같이 고쳐야 하는지, AI 가 다시 번역하는지 모르겠다
2. **`늘리기` 가 몇 초인가?** 줄 버튼은 `늘리기` 로만 적혀 있고 우클릭 메뉴에만
   `1초 늘리기` 가 있다. 1초가 맞나

## 4단계 — 결과물 · 만드는 중 (2026-09-25)

### 결과물 — 하는 일이 둘뿐이다

**골라서 보고, 내보낸다.** 고치는 일은 여기서 하지 않는다 (`편집안 열기` 로 돌아간다).
왼쪽은 촬영본별 묶음 목록, 오른쪽은 고른 것 하나. 메일 앱 문법이다.

**기본이 "이전 버전과 나란히" 인 이유**: 결과물 화면에서 사람이 진짜 묻는 건
"이게 저번 것보다 나아졌나" 하나다. 글로 설명하는 것보다 두 개를 같이 보여주는 게 빠르다.
아래에 "편집안 1과 달라진 점" 을 **사람 말로** 적는다 — "쉬는 구간 2곳을 뺐어요 −5초".
이전 버전이 없으면 하나만 보여주고 "이 촬영본의 첫 결과물이에요" 라고 말한다.

**내보내기는 "어디로" 하나만 묻는다.** 코덱 · 비트레이트 · 파일 이름을 묻지 않는다.
아이폰에서 확인하려면 사진 앱으로 가야 하므로 그게 첫 줄이다 (`AGENTS.md §2`).

### 만드는 중 — 기다리는 사람이 "멈춘 건가" 를 묻지 않게

네 묶음이다: 지금 도는 것 · 기다리는 것 · 멈춘 것 · 오늘 다 만든 것.
기다리는 것을 안 보여주면 큐에 있는 줄 모르고, 멈춘 것을 안 보여주면 다 된 줄 안다.

**멈춘 것에도 붉은색을 쓰지 않았다.** 저장 공간이 모자란 건 사람이 손대면 이어서 만들 수 있다.
노란 일시정지 아이콘 + 사람 말 이유 + `이어서 만들기` · `저장 공간 확인하기` 두 버튼이다
(`§1-6`). 이 화면 전체에서 붉은색은 한 번도 쓰지 않았다.

### 화면 목록

| 파일 | 상태 |
|---|---|
| `results-compare` | 이전 버전과 나란히 + 달라진 점 |
| `results-single` | 첫 결과물 (견줄 것이 없음) |
| `results-export-sheet` | 내보내기 — 어디로 보낼까요 |
| `results-empty` · `results-loading` | 빈 상태 · 불러오는 중 |
| `making-busy` | 도는 것 · 기다리는 것 · 멈춘 것 · 오늘 다 만든 것 |
| `making-empty` | 만드는 게 없을 때 |

### 스크린샷에 대해 알아 둘 것

- **시트는 부모 창을 떠도 안 따라온다** (AppKit 에서 다른 창이다). `results-export-sheet` 은
  시트만 따로 460×360 으로 뜬 것이다
- 이번 회차 일부는 화면이 잠들어 **빈 그림**이 나왔다. 도구가 그걸 알아채고 뷰 그리기로
  넘어가도록 고쳤다 (그림 아래 한 줄이 그 표시다). 하얀 PNG 가 커밋에 들어가는 일은 없다

### 추측한 것

1. **내보낼 곳 3개** — 사진 앱 · Mac에 저장 · AirDrop. 실제로 쓰는 경로가 이 셋인지 모른다.
   인스타그램 · 유튜브로 바로 올리는 건 넣지 않았다 (계정 연결이 필요하고 `§16` 밖이다)
2. **결과물 목록을 촬영본으로 묶었다.** 날짜로 묶을 수도 있는데, "그 영상의 결과물들" 을
   찾는 일이 더 잦다고 봤다
3. **멈춘 이유 문구** — 저장 공간 하나만 그렸다. 다른 멈춤(권한 · AI 끊김)은 문구가 다를 텐데
   무엇이 있는지 모른다

### 물어볼 것

1. **결과물을 지우는 길이 없다.** 쌓이기만 한다. 갤러리처럼 `목록에서 숨기기` 가 필요한가,
   아니면 파일까지 지우는 게 필요한가
2. **내보내고 나면 무엇이 보여야 하나?** 지금은 "사진 앱으로 보냈어요" 한 줄만 생각해 뒀다.
   내보낸 이력을 결과물 줄에 표시할지 (예: "사진 앱 · 어제") 물어본다
3. **`만드는 중` 에서 순서를 바꿀 수 있어야 하나?** 큐가 1개씩 도는데 기다리는 것이 여럿이면
   "이거 먼저" 가 필요할 수 있다. 지금은 `취소` 만 있다

## 5단계 — 첫 실행 · 설정 (2026-09-25)

### 첫 실행에서 묻는 것은 셋뿐이다

사진 · AI · 이름. 크리에이터에게 **설치 이상의 것을 요구하지 않는다** (`§1-9`) —
터미널도, CLI 설치도, "한 줄만 붙여넣기" 도 없다. 사람이 하는 일은 브라우저에서
로그인 버튼을 누르는 것뿐이다.

- **사진은 막지 않는다.** 허용하지 않아도 넘어간다. 대신 "괜찮아요, 이대로도 쓸 수 있어요" 와
  Mac 에서 직접 넣는 길을 그 자리에서 알려준다
- **AI 는 막는다.** 연결 전에는 `계속` 이 잠긴다. AI 가 없으면 편집안을 만들 수 없고
  그게 이 앱의 전부다 (`§10` — AI 없는 편집 경로를 따로 만들지 않는다)
- 권한 창이 뜨기 **전에** 무엇을 읽고 무엇을 안 건드리는지 먼저 말한다
  (영상만 읽어요 · 원본은 그대로 둬요 · 언제든 끌 수 있어요)
- 이름 단계는 **어디에 쓰이는지 바로 보여준다.** 설명보다 빠르다

### 설정은 `Settings` 씬 + `Form` 이다

앱 창에 칸으로 두지 않는다 (1단계 답). 여기 있는 것은 첫 실행에서 물은 셋과 촬영본 보관뿐이다.

**스타일 값은 설정에 없다.** 글자 크기 · 외곽선 · 자막 자리를 여기 두지 않았다.
크리에이터가 "외곽선 7px" 을 알 리 없고, 그건 재서 정하는 값이다 (`§9`).
스타일이 바뀌면 `StyleFitter` 가 재서 제안하는 게 맞는 길이다 (`§9` 2단계 이후).

### 4단계에서 고친 것

1. **사이드바가 까맣게 나온 건 캡처 탓이었다.** 화면이 깨어 있을 때 실제 창으로 다시 뜨니
   사이드바 항목 · 스튜디오 줄 · 톱니가 다 나온다. 실물 버그가 아니다.
   대신 도구가 **어느 길로 찍었는지 줄마다 찍고**(`← 실제 창` / `← 뷰 그리기`),
   뷰 그리기로 찍힌 판의 경고 문구에 "사이드바 항목" 을 넣었다
2. **샘플을 한 곳에서 꺼내 쓴다.** `planDuration` · `planSceneCount` 를 `planScenes` 에서
   계산하고 결과물 · 만드는 중 · 채팅 요약이 전부 그 값을 쓴다.
   이제 편집안 2 는 어디서나 `0:27 · 장면 9개` 이고, 이전 편집안 1 은 `0:35 · 장면 11개` 다
3. **결과물 비교에서 두 영상이 남는 높이를 다 쓴다.** 폭과 높이 둘 다로 묶어서 계산한다
4. **만드는 중 제목과 사이드바 숫자가 같은 것을 센다** — 지금 돌고 있는 것(1).
   기다리는 것 · 멈춘 것은 묶음 제목에서 따로 센다 (`기다리는 중 1개`)

### 질문 답 반영

- **결과물 지우기** → `휴지통으로 옮기기` (우클릭). 확인 문구는 "이 영상을 휴지통으로 옮길까요? /
  사진 앱으로 내보낸 건 그대로 있어요." macOS 휴지통이라 되살릴 수 있다
- **내보낸 이력** → 결과물 줄에 작게 한 줄: `✓ 사진 앱에 저장함 · 오후 2:52`
- **대기열 순서** → 그대로 둔다 (`취소` 만)

### 추측한 것

1. **보관 기간 30·60·90·180일 · 계속 두기.** 90일을 기본으로 뒀다. 실제로 얼마나 쌓이는지 모른다
2. **"쓰는 AI" 를 따로 고르게 했다.** Claude 와 Codex 를 둘 다 연결해 두고 쓰는 것만 고르는
   그림인데, 실제로 둘 다 구독하는지 모르겠다
3. **계정 표시** — `creator@example.com`. 실제 주소는 설정값이고 코드에 없다 (`§1-7`)

### 물어볼 것

1. **첫 실행에서 AI 연결을 못 하면 어떻게 하나?** 지금은 `계속` 이 잠긴 채로 멈춘다.
   "나중에 연결" 로 빠져나갈 길을 줄지, 아니면 여기서 막는 게 맞는지
2. **보관 기간이 지난 촬영본을 지울 때 확인을 받아야 하나?** 지금은 설정값대로 조용히 지운다고
   가정했다. 결과물은 지우지 않는다고 문구에 적었다
3. **첫 실행 창을 다시 볼 길이 필요한가?** 설정에 "첫 실행 다시 보기" 를 둘지
