## 정해 둔 것 (`AGENTS.md` 에서 바로 나온다)

- **도구는 2개뿐** — `read_digest(videoID)` · `write_composition(json)`. `render` 는 AI 가 부르지 않는다 (`§10`)
- **AI 는 파일을 직접 만지지 않는다.** Claude 는 `--tools ""`(기본 도구 전부 끔) + `--strict-mcp-config` +
  `--allowedTools mcp__madi__read_digest,mcp__madi__write_composition`. Codex 는 `--sandbox read-only` + 빈 작업 폴더.
  프레임 시트는 **MCP 이미지 블록**으로 준다 — 파일 읽기 권한을 주지 않아도 된다
- **`write_composition` 은 `parseComposition` 을 그대로 쓴다.** 실패하면 `CompositionError` 문장을 그대로 돌려줘 고치게 한다.
  `style` 은 AI 가 쓰지 않는다 — 앱이 `StyleStore.latest()` 를 찍는다 (`§5`). AI 가 적어 보내면 거절한다
- **자동 렌더하지 않는다** (`§10`) — 첫 진입은 편집안 초안까지. 렌더는 사용자가 고른다 (화면은 6단계)
- **둘 다 필수** (`§3`) — Claude · Codex 둘 다 판정에 들어간다
- **AI 미연결이면 스폰하지 않는다** (`§10`). 상태만 DB 에 남기고 문구 키를 `docs/design/copy-keys.md` 에 넘긴다
- **CLI 설치 · 로그인 대행은 6단계**(배포)다. 4단계는 "설치됐는가 · 로그인됐는가" 를 **알아내기**까지만 한다
- self-eval(게이트 실패 되먹임)은 5단계다. 4단계 AI 는 **한 턴**이다 — 도구 오류로 고쳐 쓰는 것은 같은 턴 안이다

## 결정

- **① MCP 서버 — 번들 안 별도 도구 `madi-mcp` (2026-09-27).** `Contents/MacOS/madi-mcp`, MadiKit 만 링크한다.
  앱 실행 파일의 `--mcp` 모드도 있었지만, 그러면 `@main` 앞에서 갈라야 하고 잘못 가르면 사진 감시 · 큐 · 모델 받기가
  AI CLI 의 자식 프로세스에서 돈다. 별도 도구는 그럴 길이 구조적으로 없다. `build-universal.sh` 는 번들 안 Mach-O 를
  전부 합치므로 손대지 않았다.
  서버 하나는 **영상 하나 · 편집안 id 하나**에 묶여 뜬다 (`--video` · `--composition` · `--revision-of` · `--db`) —
  AI 는 다른 영상을 못 읽고, 앱은 턴이 끝난 뒤 볼 편집안 id 를 미리 안다. AI 가 여러 번 쓰면 같은 id 를 덮어쓴다.
  `write_composition` 은 앱이 채우는 칸(`id` · `videoId` · `templateId` · `templateVersion` · `style` · `revisionOf` · `createdAt`)을
  AI 가 적으면 거절하고, 원본 구간이 영상 길이를 넘는지도 본다 (`validate` 는 영상 길이를 모른다)

- **② 모델 — 지정하지 않는다. CLI 기본값을 쓰고 기록한다 (2026-09-27).** 구독 등급마다 쓸 수 있는 모델이 달라,
  앱이 박은 모델이 크리에이터 구독에 없으면 턴이 실패한다. Claude 는 `init` · `result` 에 모델 이름이 온다
  (2026-09-27 기본값 `claude-opus-5-5`). Codex 는 알려 주지 않아 CLI 판만 남는다. Codex 는 사용자 설정을 무시하고
  띄우므로(`--ignore-user-config`) 사용자가 `config.toml` 에 적은 모델도 쓰지 않는다 — CLI 기본값이다.
  CLI 판이 바뀌면 결과가 달라질 수 있다. 그건 `events` 의 판 · 모델로 추적한다

- **자막은 앱이 채운다 (2026-09-27).** AI 는 장면의 원본 구간만 고르고 `captions` 를 적지 않는다 (적으면 거절).
  저장할 때 앱이 그 구간에 **온전히 들어온 낱말**을 `CaptionSplitter` 로 끊어 채운다 (`Madi/Templates/CaptionFiller.swift`).
  이유: 다이제스트 전사는 문장 단위라 AI 는 낱말 시각을 모른다 — AI 가 시각을 쓰면 G6(±0.15초)를 맞출 길이 없다.
  그리고 분절은 템플릿 값이다 (`§9` — 공개본 10편에 맞춘 분절기, 2단계 G5 · G6 10/10).
  전사 오타 교정은 촬영본으로 오타율을 잰 뒤에 정한다
- **영문 보조 문구 — AI 가 문장마다 번역, 앱이 나눈다 (2026-09-27).** `write_composition` 의 `secondary` 인자로
  `{sentenceStart, text}` — 문장은 다이제스트 TRANSCRIPT `[시작-끝]` 의 시작 값으로 짚는다. 앱이 그 문장에 걸린
  자막 덩어리들에 영어 낱말을 시간 순서대로, 한글 글자 수 비율로 나눠 붙인다.
  근거: 공개본 프레임에서 영문은 덩어리 번역이 아니라 **문장 번역을 나눈 것**이었다 — "잘 들어?" 아래 "me!",
  "중간 관절이라서" 위 "your hip and ankle,", "이거 10번만 해봐도" 아래 "Just try this 10 times,".
  ⚠ 나누는 비율은 **재지 않은 잠정 규칙**이다. 비우면 영문 없이 만든다 (10편 중 2편)
