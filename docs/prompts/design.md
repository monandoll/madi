## 제품이 뭔지

운동·재활 숏폼 크리에이터 **한 명**을 위한 AI 영상 편집 앱이다.
그 사람은 물리치료사이고, 인스타 릴스 12.5만 팔로워, 유튜브 4만이다.
**편집 지식이 없다. 타임라인을 못 읽는다. 터미널을 모른다.**
아이폰으로 찍고, Mac 앱을 열면 영상이 이미 거기 있고, 말로 요청하면 결과가 나온다.

목표는 편집 2~3시간 → 10분이다.

## 네가 할 일

SwiftUI 로 구현 가능한 **화면 설계 + 디자인 토큰**을 만든다.

### 설계할 화면

| 화면 | 내용 |
|---|---|
| 첫 실행 | 사진 접근 권한, AI 연결(Claude/Codex 중 선택·로그인), 스튜디오 이름 입력 |
| 갤러리 | 첫 화면. 들어온 촬영본 카드 그리드. 길이·날짜·결과물 개수 |
| 편집안 상세 | 왼쪽 = 미리보기 + 장면 카드 목록 / 오른쪽 = 채팅 / 아래 = 추천 칩 + 입력 |
| 장면 카드 | 썸네일 · 자막 문구 · 길이 · 역할(훅/시범/설명/마무리). **여기서 빼기·늘리기·자막 고치기** |
| 결과물 | 만들어진 영상 목록, 이전 것과 비교, 내보내기 |
| 설정 | AI 연결, 스튜디오 이름, 보관 기간, 사진 폴더 |
| 상태 | 만드는 중 진행률, 실패 안내 |

### 하드 규칙

1. **전문 용어 금지.** "인코딩"→"만드는 중", "컴포지션"→"편집안", "리프레임"→"화면 잡기",
   "트랜스크립트"→"자막", "렌더"→"만들기". 사용자가 못 알아듣는 단어가 하나라도 있으면 실패다.
2. **풀 타임라인 편집기를 그리지 않는다.** 트랙·키프레임·눈금자 없음.
   대신 **장면 카드**로 구조를 보여준다 (`AGENTS.md §1-3`).
3. **오류는 알림창이 아니라 채팅 안에 AI 말투로.** 붉은색은 진짜 실패에만.
   AI 미연결은 오류가 아니다 — 붉게 표시하지 않는다.
4. **타이핑 없이도 쓸 수 있어야 한다.** 추천 칩("숏폼 뽑아줘", "쉬는 구간 잘라줘" 등)으로
   주요 동작이 가능해야 한다.
5. **다크 모드 안 만든다.** 라이트 하나.
6. **iOS 화면을 그리지 않는다.** macOS 전용이다. 아이폰은 촬영만 한다.
7. macOS 네이티브 관습을 따른다. 웹앱처럼 보이면 안 된다.
   시스템 폰트·표준 컨트롤·표준 여백을 우선한다. 커스텀 컴포넌트는 꼭 필요할 때만.

### 절대 건드리지 말 것

⚠ **영상 안에 들어가는 자막 스타일은 디자인 대상이 아니다.**

`AGENTS.md §9` 의 실측표(본문 글자 높이 3.59%, 아래끝 0.2352, 보조 0.204, 12자, 고정 크기,
강조색 없음)는 크리에이터 실제 영상을 픽셀로 재서 나온 **사실**이다. 취향이 아니다.
`Madi/Templates/` 아래 값들을 "더 예쁘게" 바꾸자고 제안하지 않는다.

앱 UI 디자인 토큰과 영상 자막 토큰은 **완전히 별개**다. 섞지 않는다.

## 산출물

`docs/design/` 아래에 만든다. **Swift 코드는 쓰지 않는다** (개발 담당이 구현한다).

1. `docs/design/tokens.md` — 색 · 간격 · 라운드 · 타이포 · 상태색.
   SwiftUI 에서 바로 옮길 수 있게 이름과 값을 정확히 적는다.
   전작 토큰(`git show legacy/v0.2:CLAUDE.md`)을 출발점으로 쓰되 macOS 네이티브에 맞게 조정한다.
2. `docs/design/screens.md` — 화면별 레이아웃 명세.
   영역 구분 · 크기 · 여백 · 상태(빈 상태 / 로딩 / 실패) · 상호작용.
   ASCII 다이어그램이나 표로 그린다. 이미지 안 만들어도 된다.
3. `docs/design/copy.md` — 모든 UI 문구. 버튼 · 라벨 · 빈 상태 · 오류 메시지 · 추천 칩.
   개발이 `Madi/UI/Copy.swift` 한 파일에 그대로 옮긴다. **문구 하드코딩을 막기 위한 단일 출처다.**
4. `docs/design/decisions.md` — 왜 그렇게 했는지. 특히 전작 시안과 달라진 부분과 이유.

## 작업 방식

- 추측한 것과 근거가 있는 것을 구분해서 적는다. 근거는 파일 경로나 프레임 파일명으로 인용한다.
- 화면을 한 번에 다 내놓지 말고 **갤러리 → 편집안 상세 → 나머지** 순서로 내고 확인을 받는다.
  편집안 상세가 이 제품의 본체다. 거기에 시간을 가장 많이 쓴다.
- `AGENTS.md` 를 수정하지 않는다. 원칙과 충돌하는 게 있으면 `decisions.md` 에 적고 물어본다.
- 커밋은 작게. `docs/design/` 밖의 파일을 건드리지 않는다.
