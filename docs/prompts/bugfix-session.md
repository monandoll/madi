# 다음 세션 — 버그 잡기 (2026-09-29 작성)

이번 세션의 **주 업무는 버그 잡기**다. 새 기능은 만들지 않는다. 크리에이터(쌤)에게 줄 수 있는 앱을 만드는 게 목표다.
사용자는 "버그가 끝도 없이 나온다" 고 했다. 지난 세션의 버그는 거의 다 **사용자가 직접 눌러 보다가** 찾았다 —
에이전트는 앱을 누를 수 없었다. 이번에는 **에이전트가 먼저 찾는다.**

   `xcodegen generate` → `xcodebuild -project Madi.xcodeproj -scheme Madi -configuration Debug -destination 'platform=macOS' -derivedDataPath build test`

   - 없으면 **바로** 사용자에게 요청한다: 시스템 설정 > 개인정보 보호 및 보안 > **손쉬운 사용**에서 터미널 앱을 켜 달라고.
     켜지면 osascript · System Events 로 누르고 `screencapture -l` 로 창을 뜬다
   - 권한을 받기 전에는 버그를 고치지 말고 기다린다. 받으면 아래 3절 목록을 **처음부터 끝까지 한 번씩 눌러 보고**,
     깨진 것을 모두 적은 목록을 먼저 사용자에게 보여 준 뒤 하나씩 고친다

## 쌤 영상이 기준이다 (필수)

결과물이 "좋은지 · 이상한지" 는 **쌤(크리에이터) 영상과 나란히 놓고** 판단한다. 우리 규칙 · 우리 짐작 · 일반적인 숏폼 상식이 기준이 아니다.
지난 세션에 "컷이 너무 타이트하다" 는 말을 듣고서야 쌤 완성본을 쟀더니 우리 컷이 말끝을 자르고 있었다 — 처음부터 봤으면 찾았을 것이다.

- **언제**: 결과물 품질에 닿는 것은 전부 — 컷 · 호흡 · 장면 길이 · 자막(크기 · 위치 · 분절 · 영문) · 화면 잡기 · 훅 · 길이 · 말 비율.
  버그를 고치기 전에도, 고친 뒤 "됐다" 고 말하기 전에도 본다
- **어디**: 유튜브 https://www.youtube.com/@physila_sh (숏폼 132편) · 인스타 https://www.instagram.com/physila_sh/ .
  영상별 링크 · 받는 법 · 시험용 대용 영상 출처는 전부 **`docs/video-sources.md`**
- **무엇을**: 쌤 공개 숏폼 10편(완성본) `spike/source/{59HP4jxLFeA,8DF9jrxQM4U,EDpBGkaNJmU,L469kzZZe1E,lzDW-9ITfWU,nCshtY04NiY,RnP7b0JFWj4,UzemW44yzSo,Wp7dWPpiFew,xaUpqHAQjo4}.mp4`
  · 프레임 `reference/*.jpg`(34장). 10편으로 부족하면 `docs/video-sources.md` 1-2 목록(132편)에서 더 받아 잰다.
  쌤 촬영 원본은 아직 없다 — 완성본은 **쌤이 어떻게 편집하는지**를 보여 준다
- **어떻게 본다**: 숫자만 보지 말고 **그림을 연다** (에이전트는 PNG · JPG 를 직접 볼 수 있다)
  - 같은 시각 프레임 뽑기: `madi-spike frames <영상> <폴더> --at 0,2,4,6` → 뽑은 PNG 를 읽어서 본다
  - 여러 편 한 장에: `madi-spike contact <출력.png> <영상…> --at 0.3`
  - 컷 호흡: `madi-spike cutpace <영상…>` (쌤 10편 기준값 — 말 끝 → 컷 0.14초 · 컷 → 첫 말 0.10초 · 장면 1.17초 · 말 90%, `docs/findings/2026-09-29-cut-breath.md`)
  - 자막 크기 · 위치: `node tools/measure.mjs <png…>`
  - 우리 결과물도 **같은 방법 · 같은 시각**으로 뽑아서 쌤 것과 나란히 본다
- **어긋나면**: 쌤 영상이 우리 규칙을 통과 못 하면 **규칙이 틀린 것**이다 (메모리 `measure-gates-against-creator-first`).
  쌤과 다른 결과를 "원래 이렇다" 고 넘기지 않는다
- 사용자에게 보고할 때 쌤 것과 우리 것을 **나란히** 보여 준다 (숫자 표 + 같은 시각 프레임)

## 3. 버그가 숨어 있을 곳 — 우선순위 순서

**아무도 눌러 보지 않았다.** 스크린샷으로 모양만 봤다.

0. **바뀌는 게 없는 편집이 새 판으로 계속 쌓인다 (증거 있음 — 제일 먼저)** — 앱 DB 에 `edit_F4AF69FC…` 편집안이 **28개**,
   01:17 에 1분 안 17개 · 23:16 에 1분 안 11개. 28개 모두 장면 · 자막이 **똑같고** id · createdAt · revisionOf 만 다르다.
   영상 끝(60.08초)에 붙은 마지막 장면에 "1초 늘리기" 처럼 아무것도 못 바꾸는 편집을 누를 때마다 "편집안 N" 이 늘어나는 것으로 보인다.
   재현(어느 버튼인지) → `AppController` 장면 편집 경로에서 **바뀐 게 없으면 저장하지 않게** → 회귀 테스트
   (확인: `sqlite3 …/madi.sqlite "select id, revisionOf, createdAt from composition where id like 'edit_%'"`)
1. **멈추기(■) · "멈추기" 버튼** — `AppController` `.plan(.stop)` 은 **줄 선 작업만** 취소한다. 이미 도는 분석 · AI 턴은 끝까지 간다.
   누르면 아무 일도 안 일어나는 것처럼 보일 것이다. 도는 작업을 실제로 끊는 길이 필요한지 확인
2. **"사진 앱에서 보기"** (갤러리 우클릭) — 사진 앱이 아니라 앱 사본 파일을 기본 앱(QuickTime)으로 연다 (`revealInPhotos`)
3. **31분 · 긴 영상으로 전체 흐름** — 분석까지만 쟀다(297초). AI 초안 → 영상 만들기 → 검사 → 결과물까지 통째로 안 돌려 봤다
4. **가로 장면 띠** (넓은 창) — 끌어다 순서 바꾸기 · `빼기 · 늘리기 · 자막` · 카드에서 자막 고치기 · 고른 카드로 스크롤
5. **촬영본 삭제** — 확인창 · 지운 뒤 목록 · 열려 있던 편집안 · 폴더 입구 파일이 휴지통으로 가는지 · 다시 안 들어오는지
6. **자막 모양 설정** — 색 말풍선(격자) · HEX 입력(읽는 부분 테스트 없음) · 자주 쓰는 3칸 바꾸기 · 미리보기 문장 입력 · 저장 판이 쌓이는지
7. **결과물 화면** — 나란히 두 영상 · "둘 다 처음부터 재생" · 다른 결과물로 옮기면 멈추는지 · 내보내기
8. **채팅** — 질문/수정 구분(AI 판단) · "앞으로도 이렇게 할까요?" · 되돌리기 · 보내지 못한 말 다시 보내기
9. **속도 조절(LoadGovernor)** — 팬 있는 개발 맥에서는 발열이 늘 "보통" 이라 조절이 실제로 켜진 적이 없다.
   멈춤 단계에서 작업이 영영 안 시작되는 일이 없는지 (`MADI_LOAD_LEVEL=paused` 로 흉내)
10. **첫 실행 · 권한** — 사진 권한 거부 · AI 로그인 풀림 · 모델 받는 중 "편집 준비" 줄
11. **컷 여유를 귀로 들어 본 적 없다** — 컷이 너무 타이트하다는 말에 쌤 완성본 10편을 재서 말 앞 0.10 · 말 끝 뒤 0.15 · 마지막 0.30초
    여유를 붙였다(`CaptionFiller.breathe`, `docs/findings/2026-09-29-cut-breath.md`). 새 초안을 만들어 컷 자리를 들어 보고,
    `madi-spike cutpace <결과물>` 로 꼬리가 쌤(0.14초)에 가까운지 잰다. 옛 편집안은 적용 안 됨 (AI 가 새로 쓸 때만)
12. 컷 시각이 예전보다 한 표본(0.2초) 늦게 잡힘 — 알고 받아들인 차이다 (`0a558d5`). 버그 아님

- 긴 작업이 도는 동안 그 빌드 폴더를 다시 빌드하지 않는다 — 긴 작업은 `build-dev/`, 나머지는 `build/`

## 5. 버그 하나 잡는 순서

0. **눌러서 재현한다** — 실제 앱에서 사용자가 하는 그대로. 고친 뒤에도 **다시 눌러서** 확인한다 (테스트 통과만으로 끝내지 않는다).
   결과물 품질에 닿는 버그면 **쌤 영상과 나란히** 본다 (위 "쌤 영상이 기준이다")
1. **재현하고 증거를 남긴다** — DB `job.error` · `event` · 로그 · 실제 창 캡처. 추측으로 고치지 않는다
2. **원인을 찾는다** (증상 말고). 예: "끝없이 기다림" 의 원인은 화면이 아니라 60.08초 경계였다
3. **회귀 테스트를 쓴다** — `MadiTests`(엔진) · `MadiBridgeTests`(엔진 → 화면 값)
4. 화면이 바뀌면 **두 크기 스크린샷**을 눈으로 본다 (좁은 창에서 세로 목록 · 넓은 창에서 가로 띠)
5. **세션 하나 = 브랜치 하나 = PR 하나, 버그 하나 = 커밋 하나.** `rebuild` 에 바로 커밋하지 않는다 (아래 "브랜치 · PR")
6. 사용자에게 **한국어로** 알린다 — 무엇이 깨졌고, 왜 그랬고, 무엇을 고쳤고, **아직 확인 못 한 것**

**세션마다 `rebuild` 에서 `fix/` 브랜치 하나를 떼서 PR 하나로 올린다. 버그마다 커밋을 따로 하고 같은 브랜치에 계속 푸시한다.**
(2026-09-30 버그마다 PR 을 나눴더니 사용자가 "하나의 PR 로 합쳐야지" 했다 — #38~#42 를 #43 으로 합쳤다)
원격 `monandoll/madi`, `gh` 는 monandoll 로 로그인돼 있다.

```
git switch rebuild && git pull --ff-only
git switch -c fix/bugfix-<날짜>              # 세션에 한 번
# 버그마다: 고치고 · 테스트 · 다시 눌러 확인
git commit                                   # 버그 하나 — 무엇이 · 왜 · 어떻게 확인했는지
git push                                     # 같은 브랜치에 계속
gh pr create --base rebuild ...              # 세션에 한 번. 버그가 늘면 본문 표를 고친다 (gh pr edit)
```

- PR 대상(base)은 **`rebuild`** 다 (`main` 아님)
- PR 본문: 무엇이 깨졌나 · 원인 · 고친 것 · **확인한 것** (눌러 봄 / 스크린샷 / 테스트 / 쌤 영상과 비교) · **확인 못 한 것**.
  본문 끝에 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
- **머지는 하지 않는다** — 사용자가 한다. PR 링크를 보고한다
- CI 는 PR 에서 돌지 않는다 (`AGENTS.md §14` — 단계 태그 · 수동 실행에서만). 로컬 테스트가 통과해야 PR 을 만든다

## 6. 지킬 것

- 답은 **한국어로만** (영어 로그를 설명할 때도)
- 훅(`.claude/hooks`)은 건드리지 않는다
- 릴리스 공개 · 공개 저장소 만들기는 **묻고** 한다. 공증 자격 증명 · Sparkle 키 백업은 사용자가 한다
- 코드에 사람 이름을 넣지 않는다 (`§1-7`)
- AI 턴은 사용자 Claude 구독을 쓴다 — 여러 번 돌릴 실험은 먼저 말한다
- 확인하지 않은 것을 "된다" 고 말하지 않는다. 스크린샷으로 본 것 · 테스트로 본 것 · **아무도 안 눌러 본 것**을 나눠 말한다
